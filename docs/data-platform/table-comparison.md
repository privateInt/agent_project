# PDF 표 선택과 내부 비교

2026-09-17 기준. 새 PDF 정리 결과에서 파싱 표와 OCR 표를 함께 보관하고, 본문에 사용할 후보와 근거를 기록한다. 원본 파일은 수정하지 않는다. OCR 모델이나 추론 프롬프트를 바꾸지 않고 기존 페이지별 OCR 응답을 비교에 사용한다.

## 결과 확인

Streamlit은 선택된 본문·표만 보여준다. 표 비교 UI와 비교 요약은 제거했으며 별도 후보 선택을 요구하지 않는다. 원본 파일 다운로드와 일반 원본 미리보기는 유지한다. 내부 비교 후보·선택 근거는 JSON에 남아 기존 결과와 검증 호환을 유지한다. 사용자 요청에 따른 OCR 우선 정책이며 모든 문서에서 OCR이 더 정확하다는 판정은 아니다.

Markdown은 파이프 표를 사용한다. 병합 셀을 반복 값으로 펼치되 원래 셀·병합 정보는 JSON에 보존한다. 그림에서 읽은 내용도 원래 위치의 본문에 포함한다. 기존 결과는 다시 다운로드하면 새 표시 형식을 사용할 수 있지만 그림 내부의 추가 OCR은 새 정리가 필요하다.

## 처리 방식

**빠른 작업**은 기본 꺼짐이다. 기본 모드에서는 사용자가 조회·선택한 OCR 모델을 요청 직전에 확인하고, 사용할 수 있으면 PDF·PNG·JPEG에 연결한다. 모델을 선택하지 않았거나 준비된 배포가 없거나 상태 조회가 실패하면 파서만 사용한다. 다른 모델을 자동 선택하거나 배포하지 않는다.

**빠른 작업**을 켜면 모델 선택 여부와 무관하게 파서만 사용하며 요청 직전의 배포 조회와 OCR 추론도 건너뛴다. 스캔 PDF·사진에서 읽지 못한 내용은 미확인 상태로 남는다. TXT/Markdown/HTML/DOCX/XLSX는 기존처럼 파서만 사용한다.

새 요청은 실제 선택한 방식으로 보관한다. OCR을 사용하면 기존 `ocr_deployment_id`를 보내고 파서만 사용하면 생략한다. 화면의 옵션·선택 모델을 바꿔도 이미 보낸 요청이나 응답을 잃은 요청의 재전송 본문은 바뀌지 않는다. 접수 이후 고정한 모델이 사라지면 기존 모델 식별 검증에 따라 실패할 수 있으며, 그 요청을 파서 전용으로 바꿔 재전송하지 않는다.

## 선택 규칙

| 상황 | 본문에 사용할 결과 | 표시 |
|---|---|---|
| 동일 영역의 셀 값·행열·병합이 일치 | OCR 결과 | 두 결과 일치 |
| 읽을 수 있는 OCR 표가 있고 값·병합·행열이 다름 | OCR 결과 | 확인 필요·차이 보존 |
| OCR 표가 여러 조각이거나 빈 칸/구조 불확실성이 있음 | 읽을 수 있는 OCR 후보 묶음 | 확인 필요·기존 본문 순서 유지 |
| OCR 표가 비었거나 없고 파싱 후보가 있음 | 파싱 결과 | OCR 후보 없음/빈 결과 안내 |
| 스캔 PDF로 파싱 후보가 없고 OCR 표가 있음 | OCR 결과 | 비교 불가·확인 필요 |
| 빠른 작업 또는 사용할 OCR이 없음 | 파싱 결과 | 파서만 사용·미인식 내용 보존 |

OCR 우선은 사용자 선택 정책이며 정확도 판정이 아니다. OCR 페이지의 기존 응답/좌표/토큰 검사를 통과한 표에 적용한다. 실패한 OCR 페이지는 기존처럼 native 결과와 미완료 사유를 남긴다. 후보 묶음의 OCR 표 중 내용이 빈 것이 있으면 파싱 후보가 있을 때 파싱으로 돌아간다.

비교 시 Unicode NFC와 공백·줄바꿈만 정규화한다. 숫자의 부호·구분자·앞자리 0, 문장부호·대소문자를 바꾸지 않는다. 행·열 구조가 다르면 같은 번호가 같은 의미의 셀을 가리킨다고 보장할 수 없으므로 차이 목록도 위치 대조가 필요하다. 모델 confidence, 글자 수, 빈 칸이 적다는 이유만으로 더 정확한 후보라고 판단하지 않는다. 두 추출 결과의 일치도 정답 검증은 아니다. 기존 OCR 검토 품질 상태를 자동으로 ready로 올리지 않는다.

PDF 파싱에서 물리적 셀 경계를 사용해 row_span/column_span을 복원한다. 원래 파서가 찾지 못한 OCR 표 영역은 같은 PDF의 글자 위치를 text grid로 다시 읽어 비교 후보를 만든다. OCR의 셀 값이나 병합 답을 파싱 후보에 복사하지 않는다. 영역은 OCR이 지정하므로 완전히 독립된 표 탐지 결과는 아니며 `pdf-native-text-grid-v1`로 구분한다. 추정 후보가 비교에서 불일치하면 기존 OCR을 대체하지 않는다. 스캔 PDF처럼 텍스트 층이 없으면 파싱 후보 없이 OCR 결과만 남는다.

## 저장 형식과 한도

기존 `canonical-document-v1`에 선택적 `table_comparison`을 추가한다.

- `version: table-comparison-v1`, `policy: ocr-priority-v1`. 이전 `conservative-v1` 결과도 계속 읽고 검증한다.
- 선택적 `processing: {version: "refinement-processing-v1", mode: "ocr_priority" | "parser_only"}`에 실제 요청 방식을 기록한다. OCR 우선은 OCR을 사용하도록 요청했다는 뜻이며 모든 페이지의 인식 성공을 뜻하지 않는다. Go 검증은 고정된 Job OCR identity 유무와 이 값이 맞는지 확인한다.
- `tables[]`: id, page, bbox, coordinate_system, parser_candidates, ocr_candidates.
- 각 후보는 셀의 원문과 구조·좌표를 보관한다. 모델 HTML을 화면에서 직접 실행하지 않는다.
- `status`: agreed / selected / needs_review. `selected`: parser / ocr.
- `parser_metrics`, `ocr_metrics`: 그리드의 유효성, 크기, 빈 내용·구조 문제. 정확도 점수가 아니다.
- `reasons`, `differences`, `difference_count`, `differences_truncated`로 선택/검토 근거를 보관한다.
- `result_block_ids`는 실제 본문의 블록을 가리키며 해당 블록에 `table_comparison_id`를 기록한다.
- 불확실한 비교마다 `table_comparison_requires_review` 품질 이슈를 남긴다.
- Go 검증기는 선택된 후보와 실제 본문의 셀·텍스트·위치, 블록 참조, 검토 표시 및 일치 판정을 검증한다. 예전 결과처럼 비교 필드가 없는 JSON도 허용한다.

영역 연결은 같은 페이지에서 겹치는 후보들의 묶음으로 계산한다. 한 쌍의 교집합/합집합 비율이 0.5 이상일 때만 자동 판정할 수 있고 여러 후보가 연결되면 검토 대상으로 둔다. 페이지당 후보 500개, 후보 그리드 20,000칸, 한 문서의 추가 영역 추출 50회로 제한한다. 한도 내에서 비교하지 못한 영역은 후보 없음으로 남기며 일치로 간주하지 않는다. 차이 목록은 100개까지, 두 후보의 전체 셀은 결과 크기 한도 내에서 모두 저장한다. 전체 canonical 32 MiB, 기존 OCR 페이지/시간·Job 제한은 유지한다.

Markdown/TXT와 화면 본문은 선택된 후보를 사용한다. 실제 처리 방식과 확인 필요 안내도 다운로드에 포함한다. 표 비교 요약/화면 안내는 제거하고 값·배치 확인 필요 안내만 남긴다. JSON에는 양쪽 후보와 근거를 보관한다. 추가 CPU 비교 시간은 `timings.table_comparison_ms`로 별도 기록한다. 표 비교를 이유로 OCR 재요청·병렬 요청·모델 다운로드를 하지 않는다. 빈 그림 영역의 별도 OCR은 [OCR 계약](api-ocr.md#그림-내부-글자-인식)에 따른다.

## 검증 범위

2026-09-16 그림 OCR·출력 변경의 과거 로컬 기록: Python 230개(정제 65·표 선택 22·Data UI/보관/미리보기/연결/출력 143), Go canonical/runtime 14개 통과. 정제 API·Gateway·Reconciler·정제 Job 실행 파일 4개 컴파일. 합성 OCR 응답으로 실제 PDF 렌더→그림 crop→표 선택→Go 검증→Markdown 저장 연결을 확인했다. 원본 좌표·불일치 참조·거짓 완료·빈/낮은 확률/위험 HTML 응답·추가 요청 한도/순서·파서 전용 모드와 기존 결과 호환도 검사했다.

사용자가 첨부한 `정리한-결과(2).json`의 t1/b87(4페이지)이 OCR 선택이고 그 셀을 만든 HTML이 첨부 Markdown에 정확히 들어 있는 것을 확인했다. 표 4개는 OCR, OCR 후보가 없는 별도 영역 1개는 파서 선택이었다. 1·3페이지의 그림 4개는 미인식이다. 이 응답을 재생할 때 새 crop 응답은 없는 것으로 처리해 미인식 상태가 유지되는지 확인했다. 새 그림 내용을 인식한 것으로 기록하지 않는다.

2026-09-17 최신 첨부 결과에서는 네 crop 요청의 실제 응답을 확인했으나 모두 미인식이었다. 원본 대조에서 t1의 공정명 누락·열 이동, t3의 본문 중복을 확인했다. 따라서 OCR 우선은 유지하되 이번 샘플의 표 정확도·그림 OCR을 완료 처리하지 않는다. 첨부 Markdown은 최종 JSON 변환 결과와 정확히 일치했다. [최신 점검](testing-acceptance-20260917.md)에 해시·블록·시간과 후속 검증 기준을 기록했다.

2026-09-17 후속 구현에서 아래 본문 중복 방지와 crop 부분 글자 보존을 수정했다. 관련 Python 108개와 Go canonical/runtime 15개, 실제 응답 9개 재생 및 기존·수정 JSON의 Go 검증을 통과했다. 정제 API/Job 컴파일도 확인했다. 서버 Docker 빌드·새 GPU 추론·DB 검사는 별도이며 검사 출력 파일은 프로젝트 안에 배포하지 않는다.

## 일반 문단의 가짜 표 중복 방지 (2026-09-17)

OCR 페이지가 completed/partial인 경우에만 적용한다. native 후보의 구조 문제가 `missing_cells`뿐이고, 각 행의 긴 문장 셀 하나가 두 행 이상 이어지며 머리글·행 병합이 없어야 한다. 각 셀은 NFC/공백 정규화 후 30자 이상, 공백 구분 4단어 이상이어야 한다. 이 문장들을 행·열 순서로 이은 문자열 전체가 동일 페이지의 한 OCR 문단에 연속으로 들어 있고, 그 문단 bbox가 표 bbox 전체를 포함할 때 본문에 가짜 표를 다시 넣지 않는다. 겹치는 OCR 표가 있으면 이 규칙을 적용하지 않는다.

숫자·순서·문장 일부가 다르거나 좌표가 벗어나거나 유효한 표이면 후보를 유지한다. parser 전용/실패 페이지에는 적용하지 않는다. 원래 native 후보는 `ocr.pages[].native_blocks`에 남으며 `pdf_native_table_text_already_in_ocr_body` 이슈로 생략 근거를 기록한다. 표의 값이나 모델 응답을 교정하지 않는다. 이 조건으로 모든 문서의 중복을 제거한다고 보장하지 않는다.
