# 데이터 화면 사용·검증

[데이터 관리 화면](http://192.168.0.119:14100)에서 자료를 가져오고, 내용을 정리하고, 결과를 확인한다. 자료 가져오기와 내용 정리는 버튼으로 실행하며, PDF·사진에 사용할 OCR은 준비된 목록에서 선택한다. 검증 상태는 [Data 상태](status.md)를 따른다.

## 자료 그룹

목록 위 **자료 그룹**으로 묶음을 선택한다. 각 자료 행의 **그룹** 컬럼에 소속을 표시한다. **그룹 지정** → 그룹명 입력 → **지정**으로 기존 그룹에 포함하거나 새 그룹을 만들어 포함한다. **그룹 해제**에서는 해제할 소속을 선택한다. 해제해도 원본과 정리 결과는 유지된다. **그룹 이름 관리**는 기본으로 접혀 있다. 같은 자료를 여러 그룹에 넣을 수 있다. [사용법·계약·검증 범위](api-groups.md)를 참고한다.

## 화면 사용

화면 메뉴는 **자료 목록 / 결과 확인** 두 개다. 상단 메뉴·푸른 강조색·목록 표·상태 배지·페이지 이동 배치를 모델 플랫폼과 맞췄다. 수집과 정제의 서버 역할은 그대로 유지한다.

| 화면 | 기본 동작 | 필요할 때 여는 기능 |
|---|---|---|
| 자료 목록 | **자료 가져오기** → 웹 주소/파일 업로드 → **가져오기** | 가져올 범위, 웹 가져오기 내역 |
| 자료 목록의 각 파일 | **파일 이름 선택 · 그룹 지정/해제 · 내용 정리 · 원본 다운로드 · 삭제** | 파일 이름을 눌러 원본 미리보기 |
| 결과 확인 | 정리된 본문·표 확인 → **결과 다운로드** | Markdown/TXT/JSON/원본 파일 선택, ⋯ 더보기의 원본 비교·작업 정보 |

웹에서 수집한 파일과 업로드한 파일은 원본 문서 목록에 함께 표시한다. 파일 행의 **내용 정리**를 누르면 해당 원본으로 즉시 요청한다. PDF·사진은 기본 모드에서 선택한 OCR의 상태를 클릭 직전에 확인한다. 사용할 수 없으면 파서만 사용한다. **빠른 작업**을 켜면 이 확인과 OCR을 건너뛴다. 응답을 잃은 요청이 있으면 다른 새 정리 버튼도 잠그고 원래 키로 확인한다.

파일 행의 **원본 다운로드**는 클릭할 때만 그 파일을 가져온다. 목록 조회·검색·페이지 이동으로 파일 전체를 미리 내려받지 않는다. `AI_Engineer_sample.pdf`를 업로드했다면 같은 파일명/확장자와 동일 바이트를 다시 저장한다. 원본 ID·서버 주소·메타데이터를 행별로 고정하고 크기·SHA-256 검증에 실패하면 다운로드를 실패 처리한다. 실패 시 버튼을 다시 누르거나 **파일 이름**을 눌러 원본 상세에서 파일 오류를 확인한다. 원본을 정제하거나 변환하지 않는다.

웹 수집 요청의 진행/실패 상태와 주소별 첨부 묶음은 접힌 **웹 가져오기 내역**에서 확인한다. 아직 파일이 없는 수집 요청도 여기에 남는다. 완료 상세를 확인하면 파일 목록 캐시를 비워 **← 자료 목록**으로 돌아왔을 때 새 자료를 조회한다. 목록의 **조회 / 새로고침**은 파일과 웹 내역을 갱신한다. 기존 수집 상세·원본 상세·요청 복구 URL은 계속 동작한다.

웹 주소를 가져오면 해당 주소의 수집 결과와 파일 목록을 보여준다. 파일을 선택하면 내용을 확인할 수 있다. 검색창과 조회 버튼은 목록 위에 항상 표시한다. 검색어 입력 후 **조회 / 새로고침**을 누르면 적용하며 페이지 이동은 마지막으로 조회한 조건을 유지한다. 목록 아래에는 현재 페이지의 자료 수와 이전/다음 버튼을 표시하고 이동할 페이지가 없으면 비활성화한다. 처리 중에는 상태를 자동 갱신하며 완료·실패·취소 시 멈춘다.

업로드는 원본 저장까지 수행한다. 목록의 **내용 정리** 또는 상세의 **내용 정리하기**를 눌러야 parsing/OCR 요청을 보낸다. 파일 선택·형식 변경·조회·새로고침만으로 새 작업을 만들지 않는다. 원본 비교 화면에는 정제 실행 버튼이 없다.

내용 정리는 글자와 표를 추출하는 기능이며 문장을 새로 쓰거나 요약하는 기능은 아니다. **내용 확인 필요**는 원본과 대조할 부분, **일부 내용 미확인**은 읽지 못한 부분이 있다는 뜻이다. 실제 실행 상태와 결과 품질 상태를 구분한다.

## 목록 숨김과 파일 영구 삭제

자료 목록과 결과 확인의 각 행에 **삭제**를 제공한다. 확인창에서 대상을 확인하고 삭제 범위를 선택한다. 취소·화면 이동·일반 새로고침으로 삭제를 요청하지 않는다.

| 선택 | 결과 | 보호 조건 |
|---|---|---|
| 목록에서 삭제 | 목록에서 숨기고 원본/정리 파일을 보존 | 숨긴 원본으로 새 정리 불가. 결과는 종료 상태 확인 필요 |
| 파일까지 영구 삭제 | 대상 파일을 실제 삭제, 식별/출처 기록 유지 | 복구 불가 확인, 참조/실행 중 보호 |

목록에서 숨긴 자료는 **목록에서 삭제한 항목 포함**으로 조회한다. 원본을 영구 삭제하려면 연결된 정리 결과를 먼저 영구 삭제해야 한다. 하나의 원본 삭제가 모든 결과를 자동으로 지우지는 않는다. 숨김만 수행한 항목은 기존 상세·다운로드가 유지되지만 영구 삭제한 파일은 내려받을 수 없다.

응답을 잃거나 파일 삭제 중 오류가 나면 같은 대상의 확인창에서 다시 확인한다. 다른 행을 대신 삭제하거나 오류를 성공으로 표시하지 않는다. 열린 확인창의 서버 주소 변경·미확인 생성 요청·최신 실행 상태 확인 실패 시 삭제를 차단한다. 목록 숨김은 이미 접수한 정리 실행을 취소하지 않는다.

이 기능은 UI와 Collection·Refinement·Gateway 서버의 계약이 함께 필요하다. UI만 새로 빌드해 서버 기능까지 적용됐다고 가정하지 않는다. 실제 DB/파일 삭제 검증 범위는 [현재 상태](status.md), 당시 로컬 근거는 [변경 이력](../history/data-platform-202609.md)에 둔다. 문서 갱신이나 PDF 품질 검사로 실제 삭제를 실행하지 않는다.

## 결과 저장

**결과 다운로드**에서 형식을 선택하고 **파일 저장**을 누른다.

| 형식 | 내용 |
|---|---|
| Markdown (.md), 기본 | 제목·본문·페이지/시트 구분, Markdown 표, 그림에서 읽은 글자, 인식 품질 안내 |
| 텍스트 (.txt) | 본문과 탭으로 구분한 표 값 |
| 전체 구조 (.json) | 서버에 저장된 정제 JSON의 정확한 원본 바이트. 좌표·출처·처리 정보 포함 |
| 원본 파일 | 내용 정리에 사용한 자료의 원본 바이트와 파일명/확장자. 선택 후 **원본 다운로드** |

Markdown/TXT는 저장된 JSON을 변환하며 parsing/OCR을 다시 실행하지 않는다. Markdown 표는 파이프(`|`) 문법을 쓰며 병합 셀 값은 해당 행·열에 반복한다. 원래 병합 정보는 JSON에 유지한다. 과도한 확장·충돌 배치는 셀별 위치·병합·값 목록으로 내보낸다. 그림에서 읽은 글자와 표는 해당 페이지 본문에 `그림에서 읽은 내용`으로 포함한다. 빈 그림은 추측한 설명으로 채우지 않는다. 화면에서 생략한 글·셀도 다운로드에 포함한다. 글이나 셀이 없는 그림 블록은 화면 상단과 Markdown에 `그림 영역 4개 (1페이지: 3개, 3페이지: 1개)`처럼 합계·페이지별 개수로 한 번만 표시한다. 본문의 반복 안내는 생략한다. 이 개수는 저장된 그림 영역 수이며 PDF 내부의 작은 이미지 조각도 포함하므로 실제 삽화 수와 다를 수 있다. PDF 내부 이미지 조각 전체와 좌표는 원본 JSON에 그대로 남는다. 넓은 빈 표나 충돌하는 배치는 셀별 행·열·병합·값 목록과 변환 이유를 기록한다. RAG 청킹·임베딩·검색은 별도 단계다.

원본 파일은 선택했을 때만 조회하며 크기·SHA-256 및 결과의 출처를 확인한다. 실패하면 원본 다시 불러오기를 제공하고 정제 결과 캐시는 보존한다. 기존 결과에서도 새 정제를 실행하지 않고 사용할 수 있다. 자료 목록의 각 행에서 원본을 바로 내려받을 수 있고, 원본 보기에서는 **⋯ 더보기 → 원본 다운로드**도 사용할 수 있다.

## OCR 모델 조회·선택

제목 아래 한 줄에 배치한 **OCR 모델 조회**를 눌러 준비된 글자 인식 배포를 조회하고 **사용할 OCR 모델**에서 선택한다. 일반 LLM과 중지/준비 중인 배포는 후보에서 제외한다. 조회·모델 선택으로 새 배포나 정제 작업을 만들지 않는다. 페이지를 처음 열거나 단순 새로고침할 때 모델 목록을 자동 조회하지 않는다.

한 번에 최대 100개의 ready 배포를 GET으로 조회(5초 제한)하고 Surya OCR 프로필·vLLM 엔진·snapshot 및 status/runtime_state=ready, desired_state=running을 확인한다. 뒤에 더 있으면 **다음 OCR 모델 조회**를 제공한다. 현재 페이지에 OCR이 없더라도 다음 페이지가 있으면 전체 모델이 없다고 단정하지 않는다. 조회 실패는 이전 목록·선택을 비워 오래된 연결을 사용하지 않게 한다.

선택은 현재 브라우저 세션에 보관한다. 이미 선택한 배포가 새 목록에도 있으면 유지하며, 없으면 다른 모델을 자동 선택하지 않는다. `DATA_UI_OCR_DEPLOYMENT_ID`는 조회 목록에 해당 배포가 있을 때의 초기 선택 힌트다. 이 환경변수가 없어도 목록에서 모델을 선택할 수 있다. 모델 관리 서버 주소(`MODEL_GATEWAY_URL`)가 바뀌면 기존 목록·선택을 비운다.

PDF·PNG·JPEG는 기본 모드에서 선택한 배포를 클릭 직전 GET으로 재확인한다. 준비된 OCR이면 연결하고 표는 OCR 결과를 우선 사용한다. 모델 미선택·미배포·중지·조회 실패이면 파서만 사용한다. **빠른 작업**(기본 꺼짐)을 켜면 모델이 있어도 파서만 사용한다. 이 경우 스캔 PDF·사진은 읽지 못한 내용이 남을 수 있다. TXT/Markdown/HTML/DOCX/XLSX와 저장된 결과·원본 조회는 OCR 선택과 무관하다. 새 결과의 화면과 Markdown/TXT에는 실제 처리 방식이 표시된다.

목록은 조회 당시 Model API가 보고한 관측 상태다. 공개 API에는 관측 시각이 없어 최신 실행 가능성을 보증하지 않는다. 정제 서버가 접수 시 최신 관측(60초 이내)·실행 대상 identity를 검사하고 Job 시작 때 다시 검증한다. 접수 이후 배포가 사라지면 해당 요청은 실패할 수 있으며 파서 전용 요청으로 자동 변경하지 않는다. 이미 보내고 응답을 잃은 요청은 빠른 작업 옵션·선택을 바꾸거나 조회에 실패해도 원래 키·본문·배포 ID로 재전송한다.

## 원본 미리보기

| 형식 | 표시 |
|---|---|
| HTML | 읽기용 제목·본문·목록·표 |
| PDF | 선택한 페이지 이미지 |
| 이미지 | 이미지 미리보기 |
| DOCX | 본문·표 |
| XLSX | 시트별 저장된 셀 값 |
| 텍스트 | 글 내용 |
| 미지원 형식 | 원본 다운로드 안내 |

웹의 외부 이미지·스크립트·디자인, Word 페이지 배치, Excel 서식은 그대로 재현하지 않는다. 외부 리소스·스크립트·수식을 실행하지 않는다. 다운로드 파일명은 원본 이름과 실제 형식을 반영한다.

## 오류와 요청 복구

업로드 거절은 내용 정리 이전 단계다. 파일 형식·용량·이름·인코딩 등 원인을 확인하고 **문제 해결 정보**에서 서버 응답을 볼 수 있다. 파일 바이트·요청 본문은 진단 정보에 포함하지 않는다. **입력 수정**으로 원본을 다시 선택하며, 형식 검사 실패만으로 파일 손상을 단정하지 않는다.

응답을 받지 못하면 **요청 다시 확인**을 사용한다. 보관한 입력과 원래 키로 재전송하므로 같은 이름·옵션·파일을 수동 재입력할 필요가 없다. 접수가 확인되면 **실행 결과 보기**로 이동한다. 입력이 남지 않은 과거 링크의 **새 요청 작성**은 별개 작업을 만들며 앞선 작업을 취소하지 않는다. 기존 결과를 먼저 확인한다.

의도적으로 문제가 있는 sample2 PDF는 복구하지 않고 [원본 OCR 전환 검사](testing-ocr.md#pdf-fallback)를 따른다. 결과의 글자 인식 완료·실패·미처리 페이지를 확인한다.

본문을 읽었지만 그림 내부가 전사되지 않은 페이지는 **부분 인식**으로 표시한다. 본문·표는 보여 주고 미인식 그림은 원본 확인을 안내한다. 전체 완료 수와 합치지 않으며 `일부 내용 미확인` 경고를 유지한다. Markdown에도 같은 안내가 포함된다.

새 결과의 접힌 **처리 시간** 항목에서 실행 전 대기·준비, 실행 시간, 기본 추출, OCR 처리와 페이지별 요청 시간을 확인할 수 있다. 전체 시간과 세부 구간을 더하면 중복 계산된다. OCR 요청 시간에는 서버 대기가 포함되어 있다. 시간 조회 실패가 저장된 본문 표시를 막지 않는다. 오래된 결과는 기록된 구간만 표시한다. 상세 필드와 컨테이너 시작/저장 로그는 [OCR 처리 시간](api-ocr.md#처리-시간-기록)을 따른다.

## 이후 변경 시 화면 회귀 확인

1. 모델 플랫폼과 같은 상단 메뉴·목록 표에서 업로드 파일과 웹 자료가 함께 보이는지 확인한다. 파일 이름을 눌러 상세를 열고, 행의 원본 다운로드로 이름·내용을 대조한다. 웹 가져오기 내역을 펼쳐 진행 상태와 첨부파일 상세도 확인한다.
2. 기존 정리 결과에서 Markdown·TXT·JSON·원본 파일을 내려받는다. 그림 영역 개수가 한 번만 표시되는지 확인한다. 본문·표와 원본 비교가 유지되는지 확인한다. 이 단계에서는 새 정리를 요청할 필요가 없다.
3. [문제 PDF 원본](testing-ocr.md#pdf-fallback)의 동작은 2026-09-16 사용자가 확인했다. 다시 검증할 때는 **글자 인식 결과: 완료 2개 페이지**를 확인하고 원본의 제목·본문·숫자와 대조한다. 완료/실패 수는 페이지 번호가 아닌 개수다.
4. 목록의 내용 정리가 선택한 파일에만 요청하는지 확인한다. 처리 도중 상태가 바뀌고 완료 뒤 자동 조회가 멈추는지 확인한다. 새로고침·결과 다운로드로 새 정리 작업이 만들어지면 안 된다.

AppTest 통과는 실제 LAN 브라우저와 GPU 추론 성공의 증거가 아니다. 문제 PDF의 결과 번호를 이용한 읽기 전용 검증 명령은 [PDF 확인 절차](testing-ocr.md#pdf-fallback)에 있다.

## 관리자: 처리·보존 정책

- 웹 주소는 브라우저 수집을 기본 사용한다. 첨부 포함 켜짐, 연결 페이지 꺼짐, 최대 자료 10개이며 사용자가 범위를 바꿀 수 있다. UI 요청 한도는 파일당 8 MiB·합계 32 MiB·120초, 연결 페이지 깊이 1이다.
- 정리는 선택한 원본 ID와 기본 정리 규칙을 사용한다. PDF·PNG·JPEG에만 OCR 배포 ID를 연결한다. 빠른 작업이 꺼져 있고 선택한 OCR이 준비된 경우에만 연결하며 그 외에는 ID 없이 파서 전용으로 시작한다. 서버에서 최신 관측·identity 검증이 실패하면 요청 실패를 알린다.
- PDF는 기존 이미지/텍스트 품질/표 조건에 더해 테두리 없이 반복 정렬된 숫자 열도 OCR 후보로 선택한다. 넓은 간격으로 나뉜 3개 열(숫자 열 포함)이 4개 행 이상 반복되는 보수적 감지이며 모든 표를 찾는 것은 아니다. 표의 행·열·값을 원본과 대조해야 하고, 기존 페이지 수·시간 한도를 초과하면 미처리 상태를 유지한다. OCR 실패 시 native 텍스트와 품질 경고를 보존한다.
- 원본·결과 다운로드는 크기와 SHA-256을 검증한다. 조회·표시·다운로드는 저장된 원본을 수정하지 않는다. 서버가 저장한 canonical 텍스트/셀 구조로 표시하며 모델이 생성한 HTML을 실행하지 않는다.
- 원본 미리보기는 별도 제한 프로세스에서 입력 32 MiB·10초·CPU 6초·메모리 768 MiB를 적용한다. PDF는 최대 300페이지 범위에서 한 페이지씩 표시한다.
- 결과 미리보기는 20개 블록, 블록당 20,000자, 표 200셀·60행·20열, 셀당 4,000자 한도와 생략 안내를 사용한다. 다운로드에는 이 표시 한도를 적용하지 않는다.
- 요청 입력과 업로드 바이트는 POST 전에 UI SQLite 볼륨에 보관한다. 접수 후 임시 입력을 비우고 결과 ID를 유지한다. 기록은 7일 뒤 만료되며 다음 준비 때 정리한다. 입력 손상·보관 실패·연결 서버 불일치 시 자동 POST를 보내지 않는다.

자료 ID·해시·엔진·저장 경로는 필요한 상세에서 확인한다. 원본과 정제 결과, UI 요청 보관 볼륨은 문서/테스트 결과 파일 정리와 별개다.

## 표·그림 결과 확인

Streamlit의 표 비교 버튼·후보 선택·원본 표 영역 비교 화면은 제거했다. 결과 화면은 선택된 본문·표와 그림에서 읽은 내용만 보여준다. 원본 다운로드와 전체 문서 원본 미리보기는 유지한다. 내부 후보/선택 근거는 JSON에 보관해 과거 결과와 검증 계약을 유지한다. 표의 값·배치 확인 필요 안내는 남기되 비교 화면으로 이동하도록 안내하지 않는다.

기본 모드에서 OCR을 사용할 때 페이지 결과에 글자가 비어 있는 그림이 있으면 그 영역만 한 번 더 읽는다. 전체 페이지 OCR을 마친 뒤 문서당 최대 8개 영역, 추가 단계 최대 120초, 요청당 최대 45초와 기존 전체 540초 한도 안에서 실행한다. 성공한 글자·표는 원래 영역 위치의 본문에 들어가며 Markdown/TXT에도 포함한다. 실패·빈 응답·시간/개수 한도는 미확인으로 남긴다. 실제 OCR 요청이 추가되므로 문서에 따라 처리 시간이 늘 수 있다.

빠른 작업 또는 OCR 없음은 이전처럼 파서만 사용하며 이 추가 요청도 보내지 않는다. 이미지 OCR은 글자·표 전사이며 도형 의미·화살표 관계를 새로 설명하는 기능이 아니다. 대상은 PDF 내부 그림과 업로드한 PNG/JPEG다. DOCX 내부 이미지의 별도 OCR은 포함하지 않는다.

적용 후 기존 결과를 다시 내려받으면 Markdown 표 표시 변경을 확인할 수 있다. 새로운 그림 OCR은 PDF/이미지를 새로 정리해야 적용된다. 결과의 `그림 내부 글자 인식` 개수와 본문, 원본을 대조한다. OCR로 못 읽은 기존 결과를 화면 갱신만으로 복구하지 않는다.

2026-09-17 실제 샘플에서는 추가 그림 OCR을 실행했으나 네 영역 모두 실패했다. 3페이지 내부 글자는 아직 없고, 복합 표의 누락·열 이동과 문단 중복도 남아 있다. Markdown은 해당 최종 JSON과 일치했다. 이 결과의 완료/부분 상태와 시간은 [최신 점검](testing-acceptance-20260917.md)에 기록하며, 화면 기능의 존재를 OCR 품질 통과로 표시하지 않는다.

## 부분 그림 글자 보존 수정 (2026-09-17)

새 정리에서 읽힌 글자와 미인식 그림이 함께 있으면 읽힌 글자/표를 본문·Markdown/TXT에 보존하고 미확인 영역은 남긴다. `그림 내부 글자 인식: 0개 영역 완료 · 3개 영역 부분 인식 · 1개 영역 미확인`처럼 구분한다. 부분 인식을 완료에 합산하지 않는다. 부분 영역이 없는 이전 결과의 요약 표현은 그대로다.

저장 응답 재생에서 숫자·광고 문구·그림 제목 보존과 본문 가짜 표 중복 제거를 확인했다. 후속 서버 결과(3)에서 가짜 표 제거·부분 글자 보존을 확인했지만 흐름도 내부와 복합 표 오류는 남았다. 마지막 페이지/crop 중복 수정은 별도 재생·Job 활성화까지 확인했고 새 전체 문서 검증은 보류했다. 기존 결과 다운로드만으로 새 블록이 생기지 않으며, 현재 문서 정리를 위해 새 정제를 실행할 필요는 없다. 상세 기준은 [최신 점검](testing-acceptance-20260917.md)을 따른다.
