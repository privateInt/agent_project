# 자료 그룹 — 행별 지정·해제

2026-09-18 추가 및 행별 조작으로 개선. 그룹은 원본 `document_id`를 묶는 분류 정보다. 파일을 복제하거나 이동하지 않고, 같은 자료를 여러 그룹에 넣을 수 있다. 정제 요청과 결과는 기존 원본 ID로 연결된다. 그룹 변경으로 수집·정제 Job이나 OCR 요청을 만들지 않는다.

## 화면 사용

1. **자료 목록**의 각 행에서 **그룹** 컬럼으로 현재 소속을 확인한다. 소속이 없으면 **미지정**으로 표시한다.
2. 그 자료의 **그룹 지정** 버튼을 누르고 **그룹명**을 입력한 뒤 **지정**한다. 같은 이름이 있으면 기존 그룹에 포함하고, 없으면 그룹 생성과 포함을 함께 처리한다. 사전에 그룹을 만들 필요가 없다.
3. **그룹 해제**를 누르면 해제할 그룹을 선택할 수 있다. **해제**는 그 자료와 선택한 그룹의 관계만 제거한다. 다른 자료·다른 그룹 소속·원본·정제 결과는 유지된다.
4. 목록 위 **자료 그룹**으로 필터링하고, **전체 자료**를 선택하면 전체 목록으로 돌아간다. 이름 변경은 접힌 **그룹 이름 관리**에 남긴다. 기존 별도 생성·다중 선택 편집 폼은 제거했다.

그룹 변경은 선택한 자료 한 개에만 적용한다. 자료/그룹 조회, 팝업 열기·닫기, 입력·화면 재실행만으로 변경 요청을 보내지 않는다. 통신 실패 후에는 입력·선택과 지정 요청 키를 보존하며 같은 버튼으로 재확인할 수 있다. 그룹 해제는 자연 멱등 요청이라 같은 관계를 여러 번 해제해도 원본 삭제를 호출하지 않는다.

그룹을 바꾸면 첫 페이지부터 조회한다. **그룹 새로고침**은 그룹 목록과 자료 행의 소속을 함께 새로 읽는다. 그룹 목록을 읽지 못하면 기존 필터를 유지한다. 그룹이 1,000개를 넘으면 전체 목록인 것처럼 일부만 표시하지 않고 한도를 안내한다. 서버의 그룹 필드가 누락되거나 잘못되면 행을 **미지정**으로 오인하지 않고 조회 필요 상태를 표시한다.

## API

모든 응답은 HTTP 200이다. 그룹의 `version`은 정수다. 그룹 생성/목록과 기존 원본 목록은 Collection 서비스에 저장한다.

| Method | 경로 | 입력·결과 |
|---|---|---|
| PUT | `/api/source-documents/{document_id}/group` | `Idempotency-Key` 헤더, `{"name":"프로젝트 A"}` → 생성/기존 그룹 선택과 자료 포함을 한 트랜잭션으로 처리 |
| POST | `/api/source-groups` | `Idempotency-Key` 헤더, `{"name":"프로젝트 A"}` → 그룹 |
| GET | `/api/source-groups?limit=20&cursor=...&q=...` | `items`, `next_cursor` |
| GET | `/api/source-groups/{group_id}` | `group_id`, `name`, `version`, `created_at`, `updated_at` |
| PUT | `/api/source-groups/{group_id}` | `{"name":"프로젝트 B","expected_version":1}` → 그룹 |
| PUT | `/api/source-groups/{group_id}/documents/{document_id}` | 본문 없이 멤버 추가 |
| DELETE | `/api/source-groups/{group_id}/documents/{document_id}` | 본문 없이 멤버 제외 |
| GET | `/api/source-documents?group_id={group_id}&limit=20&cursor=...&q=...` | 기존 원본 응답 형식으로 그룹 자료 조회 |

이름으로 지정한 응답은 `{"document_id":"…","group":{"group_id":"…","name":"프로젝트 A","version":1,"created_at":"…","updated_at":"…"}}`다. 삭제/미존재 자료나 멤버 저장 실패 시 새 그룹만 남기지 않고 전체를 롤백한다. 동시 같은 이름 요청도 그룹은 하나만 생성한다.

원본 목록/상세 응답에는 현재 소속인 `groups` 배열을 추가한다. 한 페이지의 소속은 별도 배치 쿼리 하나로 읽으며 원본 바이트를 다운로드하지 않는다. `groups`는 현재 분류 정보이며 불변 파일 해시/정제 입력 버전의 일부가 아니다. 그룹 이름 변경도 다음 조회에 반영된다.

멤버 응답은 `{"group_id":"…","document_id":"…","present":true 또는 false}`다. 멤버 DELETE는 이 관계만 지우며 원본 삭제 API를 호출하지 않는다. 그룹 자체 삭제 API는 이번 범위에 없다.

- 이름은 앞뒤 공백 제거 후 1~200자, 제어문자 금지, 대소문자를 구분해 중복 금지다. 이름 변경 후에도 그룹 ID는 그대로다.
- 같은 생성 키·같은 이름은 최초 생성 응답을 재전송한다. 키를 다른 이름에 재사용하면 409다. 이후 이름 변경 내용은 GET으로 조회한다. 이 API는 유지하지만 화면의 지정은 아래 원자적 API를 사용한다.
- 이름으로 지정하는 요청의 키는 자료 ID와 정규화된 이름에 묶인다. 응답 유실 시 같은 키는 최초 응답을 반환한다. 다른 자료/이름으로 키를 재사용하면 409다. 이후 명시적으로 해제한 연결을 과거 요청의 재전송으로 되살리지 않는다. 새로 지정 버튼을 누르는 새 요청은 새 키를 사용한다.
- 이름 변경은 현재 `version`을 보낸다. 다른 변경으로 버전이 달라졌으면 409이고 새로 조회해야 한다. 응답 유실 직후 같은 변경을 재전송하는 경우는 허용한다.
- 멤버 추가·제외는 같은 요청을 반복해도 같은 상태다. 생성되지 않은 그룹/자료는 404, 잘못된 UUID·본문·쿼리는 400이다. 이미 숨겨졌거나 영구 삭제 중/완료인 자료의 추가는 409다.
- 기본 목록은 숨김/영구 삭제 자료를 제외한다. `include_deleted=true`는 숨김 자료만 표시하며 영구 삭제 자료는 계속 제외한다. 그룹 관계가 있어도 원본의 기존 삭제 보호·정제 참조 검사를 바꾸지 않는다. 숨김/영구 삭제 자료의 관계 제외는 API로 가능하다.
- 목록은 기존 keyset pagination(1~100, 기본 20)을 사용한다. 커서는 그룹·검색·숨김 포함 조건에 묶이며 다른 조건에 재사용하면 400이다. 그룹이 없거나 조회에 실패했다고 전체 원본 목록으로 확대하지 않는다.

## 저장·범위

Collection DB의 `source_groups`와 `source_group_members`를 서비스 기동 시 추가한다. 기존 원본 행을 수정하거나 기존 자료를 자동으로 그룹에 넣지 않는다. 그룹과 원본의 외래 키, `(group_id, document_id)` 기본 키로 존재·중복을 검사한다. 새 테이블을 포함해 Collection DB를 백업해야 그룹도 복원된다. 모델 플랫폼의 데이터셋/버전과는 별개다.

이번에는 업로드·수집 후 목록에서 그룹을 지정한다. 업로드 중 자동 그룹 지정, 그룹 일괄 정제/삭제, 그룹 자체 삭제, 계층 폴더, 권한, ZIP 해제는 보류다. Knowledge에서 그룹을 입력으로 사용할 때는 작업 시점의 문서 ID·해시·canonical 버전을 별도로 고정해야 한다. 변경 가능한 그룹 자체를 불변 데이터셋 버전으로 취급하지 않는다.

## 검증 범위

2026-09-18 사용자가 행별 그룹 UI에 대해 **“내가 의도한대로 잘 됐어”**라고 확인했다. 그룹 컬럼·이름으로 지정(없는 이름 생성/기존 그룹 포함)·그룹 해제의 사용 흐름을 사용자 실사용 확인 완료로 기록한다. 별도 사례별 로그가 전달된 것은 아니므로 동시 요청·장애 복구·DB 검사 각각의 서버 PASS를 새로 선언하지 않는다. 이 확인을 근거로 그룹 기능을 다음 단계의 대기 항목에서 제외한다.

로컬 Streamlit/API 클라이언트 116개, 다운로드·미리보기·요청 보존·연결 관련 35개 통과. 행별 자동 생성/기존 그룹 지정, 지정/해제 응답 유실과 재시도, 한 그룹 해제 후 다른 소속·원본/결과 유지, 이름 변경의 컬럼 갱신, 그룹 전환·오류 시 필터 유지를 포함한다. Go 변경 파일의 구문/포맷과 protobuf descriptor 생성도 확인했다.

`collection/app/groups_test.go`는 이름으로 지정하기의 동시 생성·기존 그룹 재사용·트랜잭션 롤백·현재 소속 배치 조회를 추가 검사한다. 또한 실제 PostgreSQL에서 생성 동시 재전송·이름 충돌·오래된 이름 변경·멤버 제외·원본/저장 바이트 보존·커서 범위·숨김/영구 삭제를 검사한다. `gateway/app/groups_test.go`는 REST 입력과 전달·멤버 응답 일치를 검사한다. 이 환경에서는 Go 의존성 빌드·Docker·PostgreSQL 검사를 실행하지 못했다. 서버에서 기능이 동작한다는 사용자 확인을 받았으나 **서버 Go/DB 자동 검사의 개별 실행 로그는 미수령**이다. 전달 패키지의 `check.sh`는 운영 DB와 연결하지 않는 임시 PostgreSQL로 검사하며 종료 시 테스트 컨테이너·네트워크·임시 이미지 태그를 정리한다.

최초 적용 시 제공한 순서는 패치 적용 → 콘솔 및 Go/DB 검사 → Collection/Gateway/Console 빌드·재기동 → 화면 확인이었다. 사용자 동작 확인 후 이번에는 문서만 갱신한다. 확인 기록을 남기기 위한 서비스 재기동·OCR 재배포·품질 실험 재실행은 필요하지 않다.
