> 2026-10-01 코드 검토: [현재 구현과 남은 작업](../status.md)을 함께 확인한다. 아래 날짜별 결과와 검증 한계는 당시 근거로 보존한다.

코드 대조일: 2026-10-01. 기존 Data 판단/근거 갱신일: 2026-09-21. 2026-09-18 그룹 실사용 확인 이후 Data/Knowledge 책임 경계와 PDF 제목 추정 보류 결정을 반영했다. 이 표는 전달 소스와 받은 근거의 상태이며 현재 서버를 직접 조회한 결과가 아니다. 2026-09-17 품질 마무리 결정 유지. 수집은 불변 원본 저장, 정제는 parsing·선택적 OCR과 canonical JSON 생성이며 독립 요청이다.

**현재 단계는 알려진 품질 한계를 남기고 마무리한다.** 정보 누락 최소화와 읽힌 내용 보존을 우선하며 일부 오류를 감수하고 Knowledge 설계로 이어갈 수 있다. 모든 품질 검사를 통과했다는 의미는 아니다. 이후 Knowledge의 청킹·색인·검색·선택적 rerank와 대표 12문항 비교는 구현·확인했으며 상세 상태는 [Knowledge 작업 목록](../knowledge-platform/work-plan.md)을 따른다. 현재 판단은 이 문서, 다음 구현 순서는 [로드맵](../roadmap.md), 세션 시작 절차는 [인수인계](../HANDOFF_NEXT_SESSION.md)에서 관리한다.

[그룹 최소 기능](api-groups.md)은 구현·로컬 UI 검사에 이어 사용자가 2026-09-18 실제 화면에서 의도대로 동작한다고 확인했다. 그룹 사용 흐름은 완료로 유지한다. 당시 후속이었던 Knowledge 입력 계약·청킹·출처 구현 및 실제 결과 확인은 진행됐으며 현재 다음 순서는 [프로젝트 로드맵](../roadmap.md)을 따른다. ZIP 처리는 후속 확장으로 둔다. 상세 자동 검사 로그와 사용자 실사용 확인은 구분해 기록한다.

## 최종 품질 판정

자동 영역 실험 `e5d805e6-11aa-4f0b-8f1f-5dc3a5f25240`은 실행 완료/품질 실패다. 13. Tanning의 12개 항목·수량·단위는 맞고 15. Shaving 번호도 정확했지만 연결 구조가 불완전했다. 다른 입력에는 실제 값 누락도 있다. 두 timeout이 240.311초, 전체 정제 합계가 268.743초다. 129개 코드 검사 통과가 이 샘플의 품질 통과를 뜻하지 않는다.

원래 전체 PDF의 흐름도 누락·복합 표 오류는 남아 있다. Table 2의 85셀 통과와 수동 영역의 라벨 24/24는 제한된 범위다. 정확한 비교 단위와 원시 응답 근거는 [상세 점검](testing-acceptance-20260917.md)에 둔다.

## 앞으로 유지할 사용 기준

| 상황 | 이어갈 방향 |
|---|---|
| 읽을 수 있는 본문·표·그림 글자 | 얻은 내용을 보존하고 출처와 함께 이용한다. 문서 일부 오류 때문에 모든 내용을 폐기하지 않는다. |
| 일부 오탈자·불확실한 표 연결 | needs_review와 원본 참조를 유지한다. 정확한 공정·수치 연결이 확인되지 않은 결과를 확정 정보로 다루지 않는다. |
| 미인식 그림·timeout·빈 영역 | 위치와 미인식 상태를 남긴다. 없는 문장을 만들어 채우거나 성공으로 바꾸지 않는다. |
| 문서 전체가 needs_ocr | 읽힌 블록과 미인식 영역을 구분하는 방식으로 후속 활용을 설계한다. 전체 문서 자동 제외나 무조건 정상 취급을 기본 가정으로 삼지 않는다. |
| parser와 OCR 불일치 | parser를 정답으로 자동 덮어쓰지 않는다. 원본·후보·인식 출처를 보존한다. |
| 추가 품질 실험 | 대표 사용 문서나 검색 품질에서 실제 영향이 확인될 때 다시 진행한다. 모든 기존 실험 PASS를 다음 단계의 전제조건으로 삼지 않는다. |

이 표는 사용자가 합의한 개발·후속 사용 방향이다. 기존 partial/품질 상태·원본 보존 기능은 구현돼 있지만 Knowledge의 블록별 입력·경고 보존·청킹·색인 버전 관리는 후속으로 구현됐으며 실제 확인 범위와 별도 원본 purge 미검증은 [해당 문서](../knowledge-platform/work-plan.md)에서 관리한다. ready도 의미 정확도 보증이 아니며 기존 실패 보고서를 PASS로 수정하지 않는다.

## 다음 작업과 보류

1. Data 품질 마무리 결정을 유지한다. Knowledge 핵심 관리·검색과 전용 인덱스 삭제·참조 해제는 후속 기록으로 확인했다. Agent/Tool 구현도 이후 진행됐다. 현재 다음 개발은 [전체 로드맵](../roadmap.md)을 따른다. ZIP 해제는 별도 후속 확장이다.
2. 읽힌 내용은 활용하되 미인식/불확실 상태를 전달한다. Knowledge는 제공된 블록 유형·품질·원문 위치를 보존하며 읽힌 내용을 청킹하고 미인식 영역을 명시적으로 기록한다. 이 과정에서 문서 구조를 재판정하지 않는다.
3. 복합 표·흐름도·timeout 튜닝은 보류하며 실제 사용·검색에서 누락 영향이 확인될 때 다시 판단한다. 재실험은 현재의 필수 다음 작업이 아니다.
4. GPU 동시 로딩/OOM·영구 삭제·Data 저장 실패/재시작/취소·백업 등 운영 검증은 별도 후속 범위다.

## PDF 제목 추정 — Data의 별도 보류 과제

2026-09-21 사용자 결정: PDF 파싱·OCR와 제목/본문/표 구조 판별·canonical 생성은 Data가 소유한다. Knowledge는 제공된 구조를 청킹에 활용하며 text를 heading으로 재분류하지 않는다. 모델 배포·추론은 Model이 소유한다.

현재 기본 PDF 파서는 추출한 텍스트 줄을 text로 만들고, OCR의 Section-Header는 heading으로 보존한다. 일부 제목이 text인 한계는 있지만 `3.3`, `4.` 등 번호·글꼴·간격 규칙을 일반 파서에 추가하면 목록·수치·본문을 제목으로 오인할 수 있다. 여러 문서의 영향 근거와 검증 자료가 충분해질 때 Data 범위에서 다시 검토한다. 현재 착수·구현하지 않으며 Knowledge 다음 작업이나 완료 조건으로 삼지 않는다.

문서의 기존 구조를 전달하는 것과 구조를 추정하는 것을 구분하고 불확실한 내용·품질 경고를 보존한다. 향후 독립적으로 정제 정책을 바꾸면 기존 canonical을 보존한 새 결과로 검증하고, 검색 평가의 source anchor도 다시 대조한다.
