# Knowledge 사용자 화면 — 2026-09-22

Data의 자료 목록·행별 동작·상세 보기와 Model의 모델 이름·버전 선택·접힌 고급 설정을 참고해 Knowledge의 긴 테스트 화면을 세 작업 화면으로 바꿨다. 소스 구현·로컬 Node 4개 스크립트 대역 검사 후 사용자 화면에서 test1의 custom 설정 42개 빌드·기본 버전 지정·재정렬 ON 검색을 확인했다. 전체 Go 검사는 이후 실패·복구 tests 이미지에서 Gateway/app을 포함해 통과했다. 브라우저 전체 레이아웃 검사는 별도다.

## 화면과 작업

| 화면 | 기본 흐름 | 상세에서 제공하는 기능 |
|---|---|---|
| 지식 목록 | 이름으로 목록 확인 → 상세 또는 검색 | 버전 진행률, 새 버전 만들기, 기본 검색 버전 지정, 삭제, 처리 정보 |
| 지식 만들기 | 자료 선택 → 처리 설정 → 확인·시작 | 저장된 청크 재사용/자료 포함 선택, 선택적 청크 미리보기, 크기 조정, HNSW, 부모 버전 |
| 검색 | 지식 선택 → 질문 → 검색 | 검색 버전 변경, 선택적 재정렬 모델, 결과 수·자료·종류·후보 수, 점수·출처 |

사용자 화면의 ‘지식’은 기존 logical index와 동일한 리소스다. 서버 리소스/DB/검색 API 이름은 변경하지 않는다. 모델은 배포 UUID 입력 대신 등록 이름·버전·짧은 배포 구분자로 선택한다. Model의 embedding/reranker profile을 확인하므로 기존 llm 등록도 실제 capability가 맞으면 사용한다. 준비된 배포 20개씩 조회하고 더 보기로 이어간다. profile/이름 조회는 최대 네 작업이 동시 실행하며 일부 조회 실패는 표시한다. 목록 진입·모델 선택·폴링은 GET만 수행한다.

진행 중인 선택 작업은 화면이 보이는 동안 5초 간격으로 조회한다. 색인/미리보기의 실패를 자동으로 재실행하지 않는다. 완료된 버전은 ‘검색에 사용’을 명시적으로 눌러 기본 검색 버전으로 지정한다. 생성이나 새로고침이 활성 버전을 바꾸지 않는다. 기본 검색 버전이 첫 페이지 밖에 있으면 그 버전을 직접 조회한다. 기본 버전이 없으면 사용자가 보존된 버전을 선택한다.

원본 품질 경고와 출처는 유지한다. 내부 JSON과 점수는 접힌 상세에서 확인한다. 검색 처리 시간은 Knowledge 응답의 timings 값이며 별도 질문 임베딩/브라우저 전체 시간을 뜻하지 않는다. 이름을 아직 조회하지 못한 과거 자료는 짧은 식별자로 구분한다.

## 생성과 재확인

새 지식의 ‘생성 시작’은 기존 CreateIndex → CreateBuild 두 요청을 실행한다. 기존 지식의 새 버전은 CreateBuild만 실행한다. 새 자료는 build의 chunking 입력을 사용해 서버가 청킹부터 색인까지 진행한다. 미리보기는 독립 작업이며, 해당 결과를 그대로 쓰려면 ‘저장된 청크 결과 재사용’에서 고른다.

브라우저는 요청 전에 두 단계의 body와 별도 idempotency key를 localStorage에 저장한다. 등록 또는 빌드 응답이 유실되면 상단의 이어서 확인 버튼이 당시의 요청을 정확히 재전송한다. 페이지 재진입은 요청을 자동 전송하지 않는다. 보류 중에는 새 생성 요청을 차단한다. 저장소에 키를 보존할 수 없으면 새 생성 POST를 보내지 않는다. 등록만 성공하고 빌드가 명시적으로 거절되면 등록된 지식을 보존하고, 설정 수정 후 그 지식에 새 빌드를 요청한다. 자동 삭제로 실패를 숨기지 않는다.

기존 관리 요청과 미리보기의 보류 키도 그대로 읽고 재확인 버튼을 제공한다. 2026-09-22 [마감 검토](../testing/session-closeout-20260922.md)에서 이 두 경로도 저장 실패 시 전송을 막도록 보완했다. 응답 수신 뒤 보관 기록을 지우지 못하면 원래 키와 본문을 유지해 재확인한다. 이 보완은 로컬 검증 완료이며 서버 반영은 별도다. 이는 현재 브라우저의 복구 수단이며 여러 브라우저/기기 사이를 아우르는 분산 작업 잠금은 아니다.

## UUID 오류

사용자가 보고한 canonical nonzero UUID is required는 공용 validID 함수의 문구다. 여기서 canonical은 UUID 표준 표기 형식이며, 정제 결과뿐 아니라 인덱스·배포·실행·버전 식별자에도 같은 오류가 사용된다. 오류를 일으킨 실제 HTTP 요청은 제공되지 않아 특정 필드가 원인이라고 단정하지 않았다.

모델/부모 버전/정리 결과를 목록에서 고르고, 저장된 청크의 자료 범위를 체크박스로 선택하게 바꿨다. 빈 값·형식 오류·zero UUID·잘못된 범위는 생성 전 화면에서 거절한다. 선택 누락은 항목명으로 안내한다. 서버의 기존 공용 문구가 도착하면 선택 정보를 다시 확인하라는 화면 안내로 표현한다. 서버 UUID 검사나 외부 API 검증 규칙은 완화하지 않는다.

## 플랫폼 경계와 적용

Gateway의 기존 /console/model 전달에 배포 목록, 등록 모델 단건, 모델 버전 단건 GET을 추가했다. 고정 Model Gateway origin의 정해진 API만 호출한다. 배포 목록은 ready 필터, 최대 20개, bounded cursor로 제한하며 알 수 없는/중복 query, 잘못된 UUID, redirect와 과대 응답을 거절한다. 모델 배포·중지·삭제·학습 경로는 노출하지 않는다. Knowledge의 도메인 서비스나 Model 배포 책임은 변경하지 않는다.

Data 파싱·OCR·PDF 제목 판별은 이번 변경에 포함하지 않는다. Model/Knowledge Service/Job/DB와 기존 인덱스를 교체하거나 재생성하지 않는다. 직전 HNSW 패치가 적용된 소스를 기준으로 guarded patch를 적용한 뒤 Knowledge tests target을 빌드하고 knowledge-gateway만 다시 빌드·기동한다.
