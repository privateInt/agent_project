# 과거 테스트 결과 요약 및 파일 정리

2026-09-16에 업로드된 `agent_project.tar.gz`를 기준으로 정리했다. 아래 내용은 첨부 프로젝트의 기존 보고서·로그와 검증 이력의 요약이며, 이번 정리를 위해 서버나 GPU 테스트를 다시 실행한 결과가 아니다.

현재 상태는 [프로젝트 상태](../status.md), 이후 실제 PDF의 그림·표 판정은 [2026-09-17 점검](../data-platform/testing-acceptance-20260917.md)을 따른다. 아래의 미확인 표시는 당시 기록이며 후속 판정을 덮어쓰지 않는다.

## 정리 범위

| 대상 | 삭제한 파일 수 | 삭제한 크기 |
|---|---:|---:|
| `data_platform/tests/results/`의 과거 결과 | 129 | 3,648,655 bytes |
| `model_platform/tests/results/`의 과거 결과 | 41 | 580,198 bytes |
| 합계 | **170** | **4,228,853 bytes, 약 4.03 MiB** |

로그 51개, Go 테스트 JSONL 10개, 보고서·결과 사본 JSON 105개, HTML 보고서 4개를 삭제했다. 성공·실패 기록을 모두 포함한다. 상세 출력이나 결과 JSON을 다른 폴더로 옮겨 보관하지 않는다.

테스트 코드와 `tests/fixtures/`의 샘플·정답·폰트는 유지했다. `model_platform/tests/results/operations/reset.lock`은 테스트 출력이 아니라 동시 초기화를 막는 운영 잠금 파일이므로 유지했다. DB, MinIO의 원본·정제 결과, 모델, Docker 볼륨, UI의 요청 보관 데이터에는 접근하지 않았다.

## 실패 이력과 당시 미확인 사항

초기 결과에 실패가 있었으므로 전체 과거 실행을 일괄 성공으로 처리하지 않는다. CPU 정제의 `REFINEMENT_PARSE_FAILED`, OCR 모델 가져오기의 HTTP 429, UI 테스트가 0개 발견되던 문제는 후속 수정·성공 실행을 구분해 확인했다. 모델 쪽도 날짜 파싱·로그 503·학습/평가 실패 및 미완료 서빙 시도가 있었고, 뒤의 성공 보고서를 완료 근거로 사용했다. 초기 용량 점검 실패와 이후 초기화·재기동 성공은 서로 다른 시점의 기록이다.

당시 미확인 범위는 sample2 원본의 실제 GPU OCR, 최종 UI의 LAN 브라우저 조작, 대표 운영 문서 품질이었다. 이후 sample2 OCR 전환과 그룹 UI는 사용자 확인을 받았고 대표 PDF 품질은 2026-09-17 한계를 기록했다. 현재 남은 범위는 [Data 상태](../data-platform/status.md)를 따른다. 원격 GPU·다중 GPU 등 기존 문서에서 보류한 범위도 이번 정리로 완료 처리하지 않는다.

## 당시 결과 정리 원칙

현재 보관분·예산·입력자료 정책은 [통합 보관 문서](artifact-retention.md)가 우선한다. 2026-09-16에 유지했던 폰트와 미리보기는 2026-09-18 후속 정리에서 제외했다.

- 테스트는 기존대로 실행 결과를 `tests/results/`에 생성한다. 실행 중이거나 분석 중인 기록은 유지한다.
- 검증이 끝나면 날짜, 대상 기능, 통과·실패·미확인 범위, 필요한 실행 식별자만 문서에 요약하고 해당 결과 파일을 정리한다.
- 이번에 삭제한 보고서 경로로는 기존 `--resume` 또는 오프라인 품질 재평가를 할 수 없다. 새 검증이 필요하면 새 실행으로 결과를 생성한다.
- 기존 문서에 남은 UUID·결과 경로는 과거 실행을 설명하는 기록이다. 삭제된 파일이 현재 존재한다는 뜻으로 해석하지 않는다.
- 운영 잠금 파일이나 DB·MinIO·볼륨을 테스트 결과와 함께 삭제하지 않는다.

## 정리 작업 확인

첨부 원본과 비교해 지정한 결과 170개만 삭제했고 테스트 코드·fixtures·서비스 소스·설정은 유지했다. 변경된 파일·새 파일·심볼릭 링크·운영 잠금을 보존하는 정리 범위를 확인했다. 이후 문서 통합에서 일회성 `tools/`도 제거했다.

## 기존 서버 반영

전체 압축본을 덮어쓰는 것만으로 기존 결과·구문서가 삭제되지는 않는다. 최신 문서 정리의 별도 적용 파일을 프로젝트 밖에서 실행한다. 첨부 당시 경로·내용이 일치하는 파일만 정리하고, 변경된 문서·새 결과·서비스 설정은 자동 덮어쓰지 않는다. 적용 파일은 종료 후 제거할 수 있으며 프로젝트에 영구 설치하지 않는다. Docker 재빌드·재시작은 필요 없다. [적용 원칙](../operations/tips.md)을 참고한다.

## 2026-09-10 Model v1 완료 범위

2026-09-10에 확인한 Docker 단일 서버 모델 플랫폼의 완료 기록이다. 프로젝트 전체나 Data의 후속 검증 완료를 의미하지 않는다. 현재 상태는 [프로젝트 상태](../status.md), Data는 [별도 상태](../data-platform/status.md)를 따른다.

| 항목 | 확인한 근거와 범위 |
|---|---|
| 모델/데이터셋 → 단일 GPU QLoRA → adapter → vLLM | 실제 서버의 짧은 GPU smoke 완료 |
| 취소·로그·출력 복구·checkpoint·평가 | 실제 실패/취소/복구·평가·서빙 검사 완료 |
| 관리/채팅 UI | 2026-09-10 23:26 UTC 실행 이미지의 AppTest 35개, 4.890초, FAIL/SKIP 없음. API/파일 위젯은 대역 |
| 목록 삭제·전송 진행률 | 관련 Go/DB 9개 통과 |
| 초기화 도구 | 서버 Python 31개 통과, 기존 운영/재기동 단위 22개 기록 |
| 실제 초기화 | apply passed=true/phase=complete, 기동·재기동 reset/capacity/passed 모두 true |
| 당시 빈 상태 | 여섯 목록·연결 DB/버킷/볼륨·이벤트·GPU 예약 검사 통과. 현재 빈 상태 보장 아님 |
| 운영 데이터 백업·격리 복원 | 사용자 결정으로 당시 완료 기준에서 제외. 실제 복원 미검증 |

당시 MLflow 16개 실행은 soft delete했고 공유 DB·experiment·삭제 메타데이터를 유지했다. 다른 프로젝트와 공유 PostgreSQL·MinIO·Kafka, 소스·설정·이미지는 유지했다. 실제 회수 용량은 원본 파일 크기의 합으로 추정하지 않는다.

과거 JSON·로그는 2026-09-16에 [검증 요약](results-summary-20260916.md)을 남기고 삭제했다. 이 문서 정리를 위해 서버·GPU·초기화를 다시 실행하지 않았다.

### 새 변경의 검증

변경 범위에 따라 [테스트 목차](README.md)에서 검사를 선택한다. UI 검사·실행 명령은 [Playground 가이드](streamlit-playground.md)에 한 번만 유지한다. 실제 브라우저 팝업·타이머·실측 다운로드 진행률은 필요한 실제 사용 때 확인한다.

Kubernetes·원격/다중 GPU·FSDP/DeepSpeed·권한·다른 모델 품질·장시간 안정성·실제 운영 데이터 복원은 [후속 개발](../roadmap.md)로 남는다.
