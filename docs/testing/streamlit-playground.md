# 선택 상세를 팝업으로 여는 관리 화면

[화면·API 계약](../reference/streamlit-playground.md), [변경 이력](../history/model-platform-202609.md#2026-09-10-12-detail-dialogs), [현재 상태](../status.md).

관리 화면에는 모델 → 배포된 모델 → 데이터셋 → 학습 작업 목록을 유지한다. 선택한 배포·데이터셋·학습의 상세를 페이지 아래에 계속 출력하던 부분은 제거했다. 목록에서 배포의 조회 버튼이나 데이터셋·학습 이름을 누르면 상세 팝업이 열린다. 로그·취소·복구·파일 버전 추가는 해당 팝업에서 사용한다.

이전 서버는 상세 팝업 변경을 적용했고 2026-09-10 23:26 UTC 실행 중인 Playground 이미지로 **35개 AppTest가 모두 PASS**했다. 실패·SKIP이 없고 4.890초에 끝났다. 2026-09-16 채팅 모델 구분 수정은 로컬 상태/API 검사 24개·AppTest 38개를 통과했다. 이 최신 수정의 서버 빌드/브라우저 확인은 별도다.

현재 프로젝트 소스에는 관련 수정이 포함되어 있다. 필요한 코드 변경 뒤 아래 검사·빌드 절차만 실행한다.

## 1. 적용·테스트·기동

작성 환경과 사용자 서버 모두 Streamlit AppTest **35개 PASS**를 확인했다. 첨부 `붙여넣은 텍스트 (1)(20260910-232625).txt`의 명령은 docker inspect로 실행 이미지 ID를 얻어 테스트했다. API 응답과 업로드 위젯은 대역을 사용한다. 실제 브라우저의 시각·타이머 동작은 아래 화면 확인 항목을 다음 필요한 사용 때 관찰한다.

```bash
cd ~/workspace/agent_project/model_platform
(
  set -euo pipefail
  docker compose --profile playground build playground
  docker run --rm -i -e PLAYGROUND_SOURCE_DIR=/app \
    model-platform-playground:dev \
    python - -v < tests/test_playground_ui.py
  docker compose --profile playground up -d --no-build --no-deps \
    --force-recreate --wait --wait-timeout 60 playground
  docker compose --profile playground ps playground
  curl -fsS http://127.0.0.1:13100/_stcore/health
)
```

현재 소스의 UI 테스트 최종 결과가 38개 OK이고 컨테이너가 healthy인지 확인한다. 테스트 파일은 표준입력으로 전달하며 이미지 안의 /app 소스를 검사한다. COPY --chmod=0644와 UID 10001의 읽기·import 검사도 유지한다. missing ScriptRunContext 경고 자체는 실패가 아니며 최종 OK 여부로 판단한다.

Playground 교체 후 브라우저를 새로고침한다. 이전 패치의 Go/DB 검증과 이미지 전환을 완료했다면 이번 UI 변경 때문에 이를 반복할 필요가 없다. 실제 학습·배포 GPU smoke도 다시 실행할 필요는 없다.

## 2. 화면 확인

1. 관리 화면에 네 목록이 순서대로 보이고, 맨 아래에 선택한 배포·데이터셋·학습 상세가 붙지 않는지 확인한다. 기존 선택 ID가 들어 있는 관리 URL을 새 브라우저 세션에서 열어도 상세 팝업은 자동으로 열리지 않는다.
2. 배포 목록의 **조회**를 누른다. 팝업에 해당 배포 상태·종료·채팅 이동이 보여야 한다. 닫기 또는 X/ESC/바깥 클릭으로 닫은 뒤 목록·검색 조건·조회 페이지가 남는지 확인한다.
3. 데이터셋 이름을 누른다. 버전 목록 조회와 새 파일 버전 추가가 팝업 안에 있어야 한다. 닫으면 페이지 아래에 상세가 남지 않는다.
4. 학습 작업 이름을 누른다. 상태·로그·평가·취소·체크포인트 재개·출력 복구·결과 모델 이동을 팝업에서 확인한다. 읽기 전용 확인에 학습·복구 버튼을 누를 필요는 없다.
5. 상세를 닫거나 채팅으로 이동한 뒤 관리로 돌아와도 마지막 선택 상세가 다시 나타나지 않아야 한다. 팝업을 닫는 동작은 학습 취소나 배포 종료를 요청하지 않는다.

상세 팝업의 학습 상태는 5초, 배포 상태는 3초 간격으로 조회한다. 닫힌 상세의 자동 GET은 중단한다. 화면의 모델 버전 진행률 조회와 별도 채팅 상태 조회는 기존대로 유지한다. 새 학습·배포·데이터셋 추가를 명시적으로 요청해 접수되면 해당 상세 팝업으로 연결한다.

## 응답 유실과 검증 범위

응답 유실 기록은 팝업을 닫아도 유지한다. 새 세션의 **요청 화면으로 이동**을 눌렀을 때만 해당 업로드·학습 복구 폼을 열며, 같은 입력과 기존 요청 키로 확인하는 규칙은 유지한다. URL 복원·목록 선택·닫기·일반 새로고침이 POST를 자동 재전송하지 않는다. 모델 가져오기 완료에 따른 전체 화면 갱신은 추가/상세 팝업이 열린 동안 보류해 입력을 보호한다.

새 테스트 3개는 기존 선택 URL의 자동 상세 노출 방지, 닫기·화면 이동 후 상세 조회 중단과 목록 보존, 응답 유실 요청의 명시적 팝업 복원을 검사한다. 기존 32개는 등록·가져오기·데이터 업로드·학습·배포·채팅·취소·복구·멱등성을 계속 검사한다. 실제 브라우저의 배치와 X/ESC/바깥 클릭·주기 타이머는 AppTest 검증을 대체하지 않으므로 위 화면 확인에 포함한다.

## 채팅 구분 확인

채팅에서 대화 가능한 배포를 조회해 OCR이 제외되고 기존 LLM은 선택되는지 확인한다. 관리의 배포 조회에서는 OCR이 여전히 보여야 한다. 이 확인을 위해 모델을 다시 배포하거나 새 추론을 실행할 필요는 없다.
