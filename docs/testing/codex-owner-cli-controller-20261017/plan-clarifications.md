# 실제 지원 범위와 구현 경계
- 공식 문서에는 userMessage.clientId 및 clientUserMessageId 의미/queue→turn 동일성 설명이 없다. cached schema는clientId 필드를제공할뿐이다. 임의동일성을가정하지않는다. 외부owner-binding은 role/thread_id/turn_id/user_message_item_id/observed_client_id/prompt_sha256/CLIreceipt hash를명시해야하며,clientId는관측된literal과만대조한다. 로컬intent토큰을nativeID로승격0. 자동turn매핑은미연결로보고한다.
- CLI제출caller는기존intentreserve/claim/read를사용한다. journal필수clientUserMessageId는로컬correlation토큰일뿐이며기존nativeACK/binding API에가상RPCparams를넣지않는다. receipt는CLI출력원문/해시와프로세스결과이며nativeACK가아니다. stdout은private0600/상한,stderr는hash/count만보존. 출력이없거나유실되면UNKNOWN/재제출0.
- 새record_dir는PR24fixture state/installation tree 바깥의명시전용상태이며borrowedintentDB를초기화하지않는다. directory/read_file/lock/admit 등의실제PR24기능을재사용해UID/mode/ancestors/symlink와root/user/localPAUSE/schedule23-07/max3를지킨다. 테스트만/tmp전용records와명시fixture schedule/PAUSE를사용한다. submission_enabled는기본false이고미승인runtime에서실제CLI를시작하지않는다.
- 기존transport의metadata read기본권한을그대로두고명시적completion-read scope에서만thread/turns/list full/limit20/desc/boundedcursor를허용한다. constructor/socket연결을새로호출하지않고기존ownerclient만borrow한다. RPC응답없는경우재시도0, 페이지최대4/총bytes1MB/명확한정체중단. thread/items/list 새call은필요하지않으면fullturns로대체한다. fullitems가없으면불완전거부.
- 실제complete와품질gate분리: exactboundturn.completed+matchinguserMessage+final_answer만결과해시로반영. failed/interrupted/inProgress/불완전/다른role/다중매칭은성공0. 검사·review·DraftPR은기존audit_check_runs의strictREST snapshot/expectedhead/app IDs를재사용하고draftPR도repo/head/base/draft/open대조. 단순agent완료문구나CLI0을PASS로변환0. sourceorigin/independentroster의외부검증이없으면전체native_ready/merge false. 이범위에서가짜서명자값을만들지않는다.
- 설치명령서에는먼저codex_shshin로그인 또는sudo -iu codex_shshin, id -un/id -u/cwd, launcher외부SHA set-e검증,PR24고정명령서순서를명시한다. 이세션에서는실행하지않는다. PR24기존준비본은수정하지않고새PR의builder/보충명령서에기록한다.
