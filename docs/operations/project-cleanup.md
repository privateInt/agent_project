# 프로젝트 파일 정리와 보존

최신 기준은 2026-10-07 첨부 `agent_project(5).tar`다. 프로젝트 정리는 서버 DB/MinIO/Docker 볼륨·모델·사용자 홈 정리와 별개다. 정리 목록·용량과 검증 결과는 [이번 검수](../reviews/documentation-review-20261007.md)에 둔다.

## 이번 통합

날짜별 Ops 안내와 오래된 검사 JSON은 [압축 원문과 목차](../history/ops-evidence-catalog.md)로 통합한다. 현재 운영 계약은 주제별 문서로 정리하고 모든 기존 문서 링크를 이력 항목으로 갱신한다. 최신 복구/QA 서버 결과와 코드가 읽는 capacity JSON은 원래 파일을 보존한다. 같은 완료 문단을 README/상태/계획/HANDOFF에 복사하지 않는다.

정리 적용기는 검토한 파일의 이전/새 SHA-256을 확인한다. 사용자 수정이 있으면 전체 쓰기 전에 중단한다. 원본은 다운로드한 패키지 `before/`와 압축 이력에 보존하며 프로젝트에 `.patch-backups`를 만들지 않는다. 패키지의 `--rollback`은 문서만 복원한다. 패키지를 삭제하면 적용 이전 경로로 일괄 복원하는 도구는 사라지지만 압축 이력의 원문은 남는다.

## 유지할 파일

- 실행 코드·설정·키·DB·운영 데이터·lock과 테스트/fixtures는 삭제/수정하지 않는다.
- `src/ops/candidates` 코드·manifest/source pins는 실제 import/해시 검증 대상이다. 같은 코드 사본이라는 이유로 없애거나 symlink로 대체하지 않는다.
- 플랫폼별 공통 Go 코드·module 경계는 독립 빌드/소유권을 유지한다. 문서 용량 정리에서 공용 코드 의존성을 도입하지 않는다.
- 기능별 API/설치/개발 계약은 각각 소유 문서에 유지한다. 완료 이력과 기능 계약을 구분한다.

이 첨부에는 대형 DB/모델/볼륨과 기존 패치 백업이 없다. 서버의 GB 단위 사용량을 이 소스 정리로 회수했다고 주장하지 않는다. 홈 cache·가상환경·VS Code·Docker 저장소는 [별도 저장 정책](storage.md)에 따라 필요 범위만 검토한다.

## 이후 규칙

현재 완료 상태는 `status.md`, 작업 방법은 master plan, 우선순위는 `roadmap.md`, 다음 세션 환경은 HANDOFF에 한 번만 둔다. 완료한 이력은 소형 결과/통합 압축 이력으로 보관한다. 결과 예산과 입력자료는 [보관 정책](../testing/artifact-retention.md)을 따른다. 자동 삭제·정리 예약은 추가하지 않는다.
