# 준비와 첫 작업

## 준비 순서와 완료 조건

현재 판정은 [상태 문서](../status.md) 한 곳에서 관리한다. 이 문서에는 진행 순서와 완료 조건만 둔다.

| 순서 | 준비 작업 | 완료 조건 |
|---|---|---|
| P01 | 공통 정책·템플릿과 프로젝트 책임 연결 | 동일 배포판·파일 해시, 역할 경계·기존 계약·첫 작업 연결 확인 |
| P02 | 문서 검증과 GitHub 전달 | 새 링크·manifest·소스 불변 확인, 쓰기 인증·PR·검토 경로 확인. 로컬 commit과 실제 게시를 구분 |
| P03 | 서버 실행 환경 확인 | CLI·ChatGPT 계정·모델·동시 작업·권한을 [실행 준비](common/EXECUTION_SETUP.md)에 따라 실제 확인 |
| P04 | 비용·재개·보고 제어 | D24의 충전·구매 금지와 사용량 초기화 확인, checkpoint·상한·PR/상태 문서 연결 |
| P05 | 첫 작업 검사 계획과 사용자 알림 | test_agent 계획·독립 reviewer 사전 검토, 준비 완료 후 사용자에게 기능 개발 시작을 알림 |

문서 검사와 구현 담당의 자체 확인은 독립 reviewer의 승인이나 제품 인수를 대신하지 않는다. GitHub 게시 완료와 서버 worktree 동기화도 구분한다. 크레딧 미사용 강제 입증은 최신 D24에 따라 선행조건에서 제외하며, 나머지 실행 준비·검사·독립 검토 조건은 유지한다.

## 첫 기능 작업

첫 작업은 **F0a 문서 QA 인용 누락 해결**다. 목표·완료 조건·보호 대상은 [기존 계획](../plans/platform-expansion-work-plan-20261012.md)과 [프로젝트 규칙](project.md)에 연결하고 새 전체 backlog를 만들지 않는다.

1. 서버의 실제 HEAD·원본/운영 상태·필요한 환경을 읽기 조회로 확인한다.
2. [작업 템플릿](templates/task.template.md)으로 이번 작은 단위의 범위와 검사 계획을 작성한다. test_agent와 독립 reviewer의 사전 검토를 거친다.
3. 준비가 완료되면 사용자에게 본격 기능 개발 시작을 알리고 해당 단위의 구현·관련 검사·실제 인수·기록을 진행한다.
4. 기존 필수 검사를 낮추거나 운영 보류를 자동 해제하지 않는다. 완료한 다음 단위는 기존 backlog의 의존성에 따라 선택한다.

후속 작업의 순서·완료 조건은 기존 계획에서 관리한다. 이 문서에는 준비 단계와 다음 진입점만 둔다.
