## 역할 구성

사용자와 아래 여섯 역할 및 별도 reviewer를 두고 주 에이전트가 총괄을 겸임하는 구성으로 정했다. 경계와 이유는 DECISIONS.md D09~D14, 모델·추론은 D15, 동시 작업은 D16, 문제 수정의 상한은 D17~D18, 사용 정책은 D24를 참조한다. 프로젝트별 실행 권한·수정 경로·구체적인 시간과 자원 범위는 확인 전이며 실제 실행 설정은 적용하지 않았다.

| 역할 | 주 책임 | 역할 경계·협업 | 주 산출물 |
|---|---|---|---|
| front_agent | 화면 상태·상호작용·접근성·API 연결 구현 | ui_design의 화면 기준, backend의 API 계약과 연결 | 화면 코드·동작 검사 |
| backend_agent | API·도메인 로직·저장·마이그레이션 구현 | 공유 모듈·계약은 code_module과 범위 합의, 플랫폼 소유권 유지 | API/도메인 코드·계약/통합 검사 |
| infra_agent | 개발 환경·빌드·CI·배포/관측 구성 | 운영 실행 권한은 작업 범위에서 별도 확인 | 구성 코드·환경 확인·배포/복귀 절차 |
| code_module_agent | 공용 라이브러리·재사용 모듈·공유 계약 | 각 backend의 도메인 책임을 가져오지 않고 호출 계약을 정리 | 공용 모듈·사용 예·호환 검사 |
| ui_design_agent | 사용자 흐름·화면 구성·문구·상태 설계 | 실제 화면 구현은 front와 연결하고 데이터 의미는 backend와 대조 | 화면 기준·상태별 설계·검토 의견 |
| test_agent | 요구 기반 검사 계획·회귀·계약·통합·E2E·품질 검사 | D29의 사전 계획과 D38의 핵심 검사 확인을 담당. 구현과 병행해 테스트 코드 작성·실행, 실패/스킵/실제 인수 한계 확인 | 검사 계획·코드·검증 결과·누락 목록 |
