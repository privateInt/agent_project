# 검색 Tool 시험 성공과 내부 API 자동완성 후속

후속 반영: [A05 자연어 검색 구현·검증](knowledge-search-a05-20260923.md)을 추가했다. 아래는 구현 전 논의/요구 기록이며 범용 내부 API 자동완성·서비스 카탈로그는 후속으로 남긴다.

2026-09-23. 사용자가 검색 Tool 시험 성공을 알리고, 서비스·schema·실행값을 하나씩 지정하는 과정이 일반 사용자에게 어렵다며 내부 schema 자동완성을 후속 기능으로 요청했다. 이번 변경은 요구사항·검증 기록이며 자동완성 기능을 구현한 것은 아니다.

## 확인한 결과

- 사용자 첨부 `Cap 2026-09-23 11-38-57-376.png`에 실행 결과 성공, `mode: test`, `state: succeeded`가 표시된다.
- 앞선 화면의 빈 query_embedding·버전/공간/index ID 예시를 준비된 시험 입력으로 바꾼 뒤, Agent를 통한 Knowledge 검색 시험이 성공했다.
- 직접 검색 준비 명령의 5개 결과와 Agent 시험 성공은 서로 다른 근거로 기록한다. 이번 화면만으로 Agent 시험의 실제 반환 수나 게시 완료를 추가 확정하지 않는다.
- `사용 시작`에 의한 게시, 발행 후 실행, 이번 Tool의 MCP 호출·재기동 보존 및 나머지 A04 인수는 별도 확인이다. A05 자연어 검색 조합은 아직 미구현이다.

## 자동완성의 두 층

| 구분 | 사용자가 지정할 내용 | 플랫폼이 채울 내용 |
|---|---|---|
| 내부 API 등록 | 서비스·기능 선택 | 등록된 공식 계약/템플릿의 HTTP 방식·경로·입출력 schema·Path 구조, 호환되는 연결 후보 |
| 검색 Tool 설정 | 검색할 지식을 이름으로 선택 | 인덱스·버전·임베딩 공간·배포를 조회하고 호환성을 검사한 뒤 Tool 버전에 고정 |
| 실제 검색 | 자연어 질문·필요한 검색 옵션 | Model 질문 임베딩 호출, 벡터 검증, Knowledge 검색 호출과 결과 연결 |

Schema 정의 자동완성과 실제 호출값 준비는 서로 다른 기능이다. schema만 자동으로 채워도 벡터·ID를 직접 입력해야 한다면 현재의 불편이 남는다. A05에서 내부값 준비와 API 조합까지 처리해 사용자 시험 화면을 지식 선택 → 질문 입력 → 결과 확인으로 만든다.

## 구현 원칙과 범위

- 내부 Model/Knowledge/Data API는 확인된 공개 API 계약 또는 검증된 템플릿을 사용한다. 현재 모든 내부 서비스가 OpenAPI 문서를 자동 제공한다고 가정하지 않는다.
- endpoint 주소만으로 모든 입력·출력·필수 필드를 알아낼 수 있다고 가정하지 않는다. 외부 API는 OpenAPI 가져오기를 우선 활용하고, 예시 JSON에서 유추하는 schema는 후속 초안 기능으로 구분해 사용자가 검토하게 한다.
- 기존 직접 등록/OpenAPI 가져오기를 유지한다. 내부 서비스는 서비스·기능 선택으로 채우는 경로를 추가하고 JSON schema 원문 수정은 고급 설정에 둔다.
- 목록 조회·선택·schema 채우기에서는 임베딩/검색/쓰기 API를 자동 실행하지 않는다. 실제 시험은 명시적인 시험 버튼으로 실행한다.
- 기존 Connection/ConnectionVersion·비밀 참조를 재사용하고 호환되는 연결만 추천한다. 환경·연결 주소를 조용히 바꾸거나 인증 비밀을 schema에 넣지 않는다.
- 새 필수 필드·지원하지 않는 schema·버전 불일치는 구체적인 설명과 위치를 표시한다. 지원하지 않는 제약을 버려 자동완성 성공으로 표시하지 않는다.
- 실행 중 필요한 필드가 비어 있으면 `입력값이 필요합니다`와 필드 이름을 알려준다. 빈 벡터·빈 UUID 예시가 실행 가능한 입력처럼 보이지 않도록 개선한다.

## 작업 순서

1. 현재 성공한 검색 Tool의 게시·실행 및 남은 A04 인수를 확인한다.
2. 기존 A05에서 질문 임베딩 → 검색을 조립하고 질문만 받는 시험 화면을 제공한다.
3. A05 이후 서비스별 API 관리와 함께 내부 API 계약 기반 자동완성을 추가한다. A05 지식 선택에 필요한 조회/매핑은 A05 안에서 구현할 수 있다.
4. 외부 API 예시 기반 schema 유추·범용 API 조합은 추가 사례와 지원 범위를 정한 뒤 확장한다.
