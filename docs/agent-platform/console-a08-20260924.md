# A08 — Agent·업무흐름·실행 기록 화면 통합

2026-09-24. 구현·로컬 자동 검증과 사용자 서버 적용·읽기 검사 통과. [서버 확인 기록](../history/agent-platform-202609.md#a08-server-check-20260924). 사용자 화면 인수는 보류다. 페이지 확인은 사용자 요청에 따라 보류하고 아래 체크리스트로 남긴다. 답변 품질 개선도 [별도 후속](answer-quality-followup-20260924.md)으로 유지한다.

## 제공하는 기능

| 화면 | 동작 |
|---|---|
| Agent | 이름으로 검색, 기존 버전 선택·시험·발행·직접 질문 |
| 업무흐름 | 등록된 n8n 연결과 고정 Agent 버전을 이름으로 찾기, 상세 확인 |
| 기존 업무흐름 연결 | 표시 이름·n8n 편집 주소·발행된 Agent 버전으로 WorkflowLink 등록 |
| n8n에서 편집·실행 | 검증한 편집 주소를 새 탭으로 열기. n8n에 별도로 로그인 |
| 연결된 Agent에 질문 | 해당 연결에 고정된 버전의 Agent를 직접 실행. n8n 전체 Flow 실행은 n8n에서 수행 |
| 실행 기록 | Agent 질문·도구 실행 전환, 질문/Agent 이름·상태로 필터, 저장된 결과 조회 |
| Agent 실행 상세 | 호출 경로, 대기/실행 시간, 5단계 상태·소요 시간, 답변·출처 또는 오류 |

Tool 등록·자연어 검색·Agent 생성 흐름은 기존 API를 사용한다. n8n 런타임·DB·계정·키는 infra가, Tool/Agent/WorkflowLink/AgentRun은 Agent가 소유한다. Model/Data/Knowledge와 infra 실행 코드는 변경하지 않았다.

### 사용 시 알아둘 점

- **연결 등록은 기존 n8n Flow를 가리키는 참조를 저장한다.** n8n Flow의 생성·게시·복제나 웹훅 자격 발급을 수행하지 않는다. 기존 운영 Flow는 목록에 바로 나타난다.
- 연결의 이름 변경·숨김은 WorkflowLink만 바꾼다. 숨김 목록도 상태와 함께 표시하여 다시 열 수 있다. n8n 게시/실행 상태나 Agent 사용 상태를 바꾸지 않는다. 실제 Flow 중지는 n8n에서 관리한다.
- `연결된 Agent에 질문`은 실제 임베딩·검색·LLM 호출을 시작한다. 결과 다시 확인·목록 새로고침은 GET 조회만 수행한다.
- `화면 대기 멈추기`는 브라우저의 반복 조회만 멈춘다. 서버 실행을 취소하지 않으며 실행 ID를 유지한다. 다시 조회하거나, 새로고침 후 토큰을 재입력하고 실행 기록에서 찾는다.
- 이름은 표시용이며 Agent 버전/실행의 기준은 저장된 고유 ID다. Agent가 중지됐거나 고정 버전이 폐기되면 새 질문을 막고 기존 기록은 계속 조회한다.

## 화면과 API의 경계

브라우저는 Agent의 같은 출처 API만 호출한다. n8n API 키·웹훅 JWT·비밀번호를 브라우저에 전달하지 않는다. iframe·SSO·n8n UI 개조·외부 사이트로의 인증 프록시는 제공하지 않는다. 편집 링크는 http(s) origin과 검증한 workflow ID로 구성하고 `noopener noreferrer`/no-referrer로 연다.

서버에 `http://127.0.0.1:16200`으로 저장된 연결을 원격 PC에서 보면 편집 링크를 막고 접속 주소를 묻는다. `n8n 접속 주소 확인`에서 현재 PC가 접근 가능한 origin(예: `http://서버IP:16200`)을 입력한다. 이 값은 현재 페이지 메모리에만 보관하며 DB 연결 주소·워크플로·자격을 변경하지 않는다. n8n에 실제 접속 가능한지는 사용자의 네트워크/브라우저에서 확인해야 한다.

실행 목록은 Agent에 저장된 caller_context를 보여 준다. `system=n8n`, workflow ID, AgentVersion이 같은 기록만 연결별 이력으로 표시한다. caller_context는 추적 정보이지 인증 증명이 아니다. 다른 n8n 인스턴스에 같은 workflow ID·AgentVersion이 등록되면 서버를 구분할 수 없다는 안내를 표시한다. n8n 전체 실행의 성공/실패를 AgentRun 상태로 추정하지 않는다.

Agent 질문 이력은 서버에 보존된 기록이다. 도구 실행 탭은 기존 페이지 내 최근 이력과 ToolCall ID 조회를 유지한다. 목록은 cursor로 최대 5,000개까지 읽으며 필터 조건에 맞는 최신 50개를 표시한다. 상한을 넘으면 오류를 표시하며 완전한 목록으로 가장하지 않는다. 대규모 서버 검색/정렬은 후속이다.

새 WorkflowLink 저장 응답이 끊기면 입력을 고정하고 같은 본문·멱등 키로 확인한다. 이름/표시 변경 응답이 끊기면 원래 revision과 요청 값을 보관하고 GET으로 확인한 뒤 필요할 때만 다시 PATCH한다. 다른 revision 변경을 덮어쓰지 않는다. 토큰/질문/결과는 localStorage나 sessionStorage에 저장하지 않으며 연결 해제 시 Agent·업무흐름 화면 데이터도 비운다.

### 조회 API에 추가된 필드

| API | 추가 필드 |
|---|---|
| GET /api/agent-runs | agent_id, agent_version, completed_at, caller_context, error(code/stage 또는 null) |
| GET /api/workflow-links | agent_id, agent_display_name, agent_enabled, agent_version, agent_version_state |

기존 ID·입력·멱등/상태/인용 검증 계약은 유지한다. DB migration은 없다. Service/Gateway 이미지 태그와 console marker는 `a08.1`이며, `/api/status`의 실행 계약은 여전히 **a07.1 / A07 / schema 5**다. Runtime/MCP를 교체하지 않는 UI·조회 API 확장이므로 이 차이는 정상이다.

## 원격 서버 적용 — 2026-09-24 완료한 절차

아래 A08 배포 절차는 사용자 로그로 완료를 확인했다. 기록 갱신을 위해 빌드/검사를 반복하지 않는다.

기준은 `agent_platform_n8n_server_record_20260924`가 적용된 소스다. 사용자가 12개 문서 파일 적용 성공을 보고했다. 패치는 먼저 전체 대상의 기존 hash를 확인하고 불일치 시 쓰기 전에 중단한다. 실제 서버 소스 수정이 있으면 강제로 덮어쓰지 말고 차이를 확인한다. `.env`·비밀·DB 볼륨·프로젝트 밖 운영 요청 세션은 대상이 아니다.

**진행 중인 Agent 질문과 Tool 시험/실행이 끝난 뒤** 적용한다. `--before-update`는 저장된 AgentRun의 accepted/running 여부만 검사한다. 단독 ToolCall이나 n8n 전체 실행의 유휴 상태까지 보증하지 않으므로 갱신 중 새 실행을 시작하지 않는다.

```bash
(
set -e
cd ~/workspace
tar -xzf agent_platform_a08_20260924.tar.gz

python3 agent_platform_a08_20260924/apply_patch.py \
  --project-root ~/workspace/agent_project --apply

cd ~/workspace/agent_project/agent_platform
python3 ops/preflight.py --skip-port-check
python3 ops/smoke_console.py --before-update

docker compose up -d --build --no-deps --wait \
  agent-service agent-gateway

python3 ops/smoke_console.py \
  --run-id 15981e7e-7ab3-41d6-bef8-ab2924cbe67e \
  --workflow-link-id e9e79c18-9573-4772-af7f-80f410fe634c \
  --expect-error ANSWER_REFERENCE_INVALID
)
```

Service와 Gateway만 교체한다. PostgreSQL·Runtime·MCP·n8n·모델 배포를 재시작하거나 기존 운영 prepare/run을 반복할 필요 없다. 별도 서버 빌드 테스트가 필요하면 `docker build --target tests -t agent-platform-go-tests:a08.1 .`을 사용할 수 있다. DB/브라우저 통합 검사를 자동 포함하는 명령은 아니다.

마지막 검사는 화면 asset과 API 목록 필드, 원래 n8n 연결과 AgentRun의 ID/5단계/오류를 GET으로 확인한다. 토큰·본문·답변을 출력하지 않으며 HTTP 리다이렉트를 따라가지 않는다. 새 추론, 설정 변경, 요청 파일 쓰기가 없다. 목록 조회 상한을 넘으면 실패하므로 별도 확인이 필요하다.

기대 출력은 `result: passed`, `stage: A08`, `console_version: a08.1`, `inference_executed: false`다. **stored_run.state는 failed, error는 ANSWER_REFERENCE_INVALID/finalize인 것이 기존 기록 보존의 정상 결과**다. A08 조회 검사 통과를 답변 성공으로 해석하지 않는다. 원래 request ID `93218149-3ad0-45f7-81b2-48f0f72f5bcf`와 ToolCall `39eac542-0c91-4975-b2d6-434d9ad49e2e`도 출력에서 대조한다.

문제 시 기존 `~/workspace/agent_n8n_workflow` 세션과 request.json을 지우지 않는다. 같은 요청을 재실행해도 기존 실패 기록을 재사용하며 인용 문제가 자동 수정되지 않는다.

- 변경 영역 Go 패키지 검사 통과. SQL이 필요한 검사는 아래 통합 검사로 별도 실행.

- read-only smoke 두 모드를 같은 실제 테스트 API에 실행하고 모델/검색/임베딩 호출 횟수가 증가하지 않음을 확인.
- 한글 폰트가 있는 Chromium에서 데스크톱/390px 모바일 화면을 확인했다. 폰트는 검사 환경에만 추가했으며 배포 파일에는 포함하지 않는다.

검증 요약: `agent_platform/tests/results/a08-console-summary.json`. 사용자 GPU·실제 자료·운영 n8n 편집은 이 로컬 검사에서 실행하지 않았다. 이후 사용자 Docker 서버에서 Service/Gateway 빌드·Healthy·기존 DB 목록/기록 GET 검사를 통과했다. 이 배포 로그에서 별도의 Go tests target이나 전체 PostgreSQL 회귀 검사를 다시 실행한 것은 아니다. n8n 실행 코드는 그대로여서 이전에 통과한 n8n 격리 검사를 이 UI 변경을 이유로 반복하지 않는다.

## 사용자 화면 확인 — 추후 수행

주소: `http://<서버IP>:16100/console`. 기존 Agent API 토큰으로 연결한다.

- [ ] Agent·업무흐름·도구·실행 기록 메뉴와 이름 기반 선택을 이해할 수 있다.
- [ ] 기존 운영 Flow가 업무흐름 목록에 보이며 고정 Agent 버전을 확인할 수 있다.
- [ ] 현재 PC에서 접근 가능한 n8n 주소를 넣고 새 탭의 별도 로그인/편집 화면으로 이동한다.
- [ ] 기존 실패 실행을 조회하면 검색/근거/생성 성공, 출처 확인 실패가 보인다. 조회만으로 새 실행이 생기지 않는다.
- [ ] 연결된 Agent 직접 질문과 n8n 전체 Flow 실행의 차이를 이해할 수 있다.
- [ ] 새 질문이 필요할 때 실제 모델 비용/자료를 확인하고 실행한다. 성공하면 답변·인용, 실패하면 원래 코드·단계를 확인한다. 의미 품질 평가는 후속 목록으로 남긴다.
- [ ] 연결 숨김/재표시가 n8n Flow를 중지하지 않음을 확인한다.
- [ ] 모바일·긴 이름·빈 목록·오류 문구의 사용성을 확인한다.

화면 확인을 기다리느라 이미 승인된 기능 작업을 중단하지 않는다. 다음 A09에서는 대표 전체 흐름과 아직 남은 운영 답변 전달/재실행·재시작 보존 인수를 통합해 관리한다. 현재 실패를 성공으로 바꾸거나 품질 개선을 완료 처리하지 않는다.
