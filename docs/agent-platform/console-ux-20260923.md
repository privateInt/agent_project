# Agent 도구 화면 개선 — 2026-09-23

사용자는 A04 서버 화면 접속까지 확인했고, 기능과 설정이 한 화면에 많아 어렵다는 의견을 주었다. 첨부 `agent_project.tar(2).gz`에는 A04 최초 화면이 있으며 중단된 간소화 변경은 포함되어 있지 않았다. 이 소스를 기준으로 화면을 수정했다. **이번 간소화 화면은 사용자가 서버 화면 변경까지 확인**했다. 이어서 [API 직접 등록·OpenAPI 가져오기와 검색 시험](tool-registration-20260923.md)을 구현했다. 후속 패치 적용·Gateway 빌드/Healthy와 접속 토큰 입력 전 화면은 사용자 로그/화면으로 확인했다. 이후 검색 Tool 시험 성공을 확인했고 게시·발행 후 실행 확인은 남아 있다. A04 실제 HTTP·DB·재기동 인수는 접속 확인만으로 완료 처리하지 않는다.

## 기존 플랫폼과 맞춘 원칙

- Model의 이름 기반 선택·한국어 상태·접힌 고급 설정을 따른다.
- Data의 상단 작업 메뉴·목록·항목별 열기와 Knowledge의 파란 강조색·단계별 만들기를 따른다.
- 기본 화면에서 UUID·revision·MCP 식별자를 요구하지 않는다. 필요한 기술 정보는 상세에서 확인한다.
- 목록 진입·기능/버전 선택·새로고침은 조회만 수행한다. 저장·시험·사용 시작은 명시적인 버튼으로 수행한다.
- 서버의 불변 버전·시험 성공 후 게시·멱등 키·Agent 소유권 계약을 유지한다.

## 화면과 사용 순서

| 화면 | 사용자가 하는 일 | 필요할 때 여는 기능 |
|---|---|---|
| 도구 목록 | 이름/설명으로 찾기 → 열기 | 버전 선택·사용 중지/재개·버전 폐기 |
| 도구 추가: 기능 선택 | OpenAPI JSON/YAML 분석 → 이름으로 기능 하나 선택 | 이미 올린 파일, 미지원 이유, 파일 예시 |
| 도구 추가: 연결 설정 | 도구 이름 → 서비스 선택 또는 새 연결 → 저장 후 시험하기 | 연결 버전·시간 제한·외부 효과·중복 방지·원시 스키마 |
| 도구 추가: 시험·사용 | 입력값 작성 → 시험 실행 → 성공 확인 → 사용 시작 | 복합 JSON 입력·MCP/REST 연결 안내 |
| 실행 결과 | 이 페이지에서 확인한 최근 실행 선택 | 이전 실행 ID 조회·원시 결과·request ID 등 기술 정보 |

`사용 시작`은 기존 publish API, `사용 중지/재개`는 Tool enabled 변경이다. 폐기는 기존 retire API다. 중지/폐기에는 대상을 확인하는 창을 둔다. 이름은 표시용이며 요청은 기존 고유 ID와 고정된 버전을 사용한다. 목록의 `등록됨`은 enabled 상태의 도구가 등록되어 있다는 뜻이며 게시 완료를 의미하지 않는다. 정확한 버전 상태는 열기에서 확인한다.

입력은 고정 속성의 object와 string/integer/number/boolean/enum 조합이면 입력칸으로 제공한다. 선택 항목은 포함을 켜야 전송하며 false·빈 문자열·미포함을 구분한다. 배열·nullable·자유 속성·복합 schema는 JSON 편집을 제공한다. form의 숫자는 문자열 검증 후 JSON 숫자 원문으로 조합하며 JSON 모드 원문도 그대로 전송한다. 최종 schema 검증은 서버가 수행한다. JSON에서 입력칸으로 돌아갈 때는 이전 입력칸 값으로 돌아간다는 확인을 받는다.

연결은 이름으로 고르고 현재 연결 버전을 기본 선택한다. 이전 버전이 필요하면 고급 설정에서 바꾼다. 인증 정보는 실제 키 대신 서버의 참조 이름과 revision을 입력한다. API Key는 이름/전달 위치까지 맞는지 확인한다. 외부 효과는 HTTP method와 관계없이 기존 보수적 기본값인 `write`를 유지한다. 변경 가능 API 실행 전 확인을 받고 시험도 실제 서비스에 요청한다.

접속 토큰·입력·최근 실행 목록·미확인 요청 키는 현재 페이지 메모리에만 존재한다. 새로고침 뒤 토큰을 다시 입력해야 하며 최근 실행 목록은 초기화된다. 서버 저장 기록은 보존되고 실행 ID로 조회할 수 있다. 결과 화면은 DB 전체 이력 목록이 아닌 이 페이지에서 확인한 최근 최대 50개다.

## 실패·중복 처리

- 진행 중에는 버튼/입력과 선택을 잠가 중복 클릭·늦은 응답에 의한 선택 변경을 막는다.
- 응답이 유실된 POST는 같은 원문·멱등 키로 재확인한다. 같은 경로에 다른 입력을 전송하려 하면 막는다.
- Tool 등록 후 버전 저장은 두 단계다. 두 번째 저장 요청과 성공 응답을 보관해 응답 유실/목록 새로고침 실패 후 같은 버튼으로 이어간다.
- 호출 접수 ID를 받았으면 결과 조회 실패 후 실행을 다시 만들지 않는다. 실행 결과에서 기존 ID를 조회한다.
- accepted/running은 약 2초 간격으로 최대 130초 조회한다. terminal 결과에서는 조회를 멈춘다. 시간 초과 시 기존 실행 조회 버튼을 제공한다.
- unknown/external_pending은 성공으로 표시하지 않으며 외부 서비스 확인을 안내한다.
- 미확인 요청/실행이 있을 때 페이지를 벗어나려 하면 브라우저 이탈 확인을 요청한다. 브라우저가 확인창을 보장하지 않으므로 실행 ID를 보관한다.

## 검증 범위

`node src/platform/agent/tests/console_ui_test.cjs`는 실제 배포 HTML의 ID와 JS를 읽어 DOM/API 대역으로 검사한다. 27개 검사 묶음이 통과했다. 단계 이동·조회만 수행하는 진입·미지원 이유·필수 입력·시간 제한·연결 해제·시험 전 게시 거절·실행·게시·결과 조회·새 버전·응답 유실/같은 키 재확인·중복 클릭·숫자 원문·JSON fallback·인증 불일치·토큰 비저장을 포함한다.

JS 문법 검사도 통과했다. 이 환경에는 Go/Docker와 실행 가능한 Chromium이 없어 새 화면의 실제 브라우저 레이아웃·접근성·Gateway 이미지 빌드·실제 PostgreSQL 검사는 수행하지 않았다. Chromium 설치 시도도 다운로드 파일이 비어 실패했다. 이 기록을 기존 A04 최초 화면의 과거 브라우저 통과 기록과 합산하지 않는다. 사용자 서버에서는 아래 적용 후 화면 표시와 본인 API 시험을 확인한다.

## 기존 A04 서버에 화면만 적용

전용 패치는 첨부 소스와 파일별 해시를 비교한다. 다른 변경이 있으면 쓰기 전에 중단한다. 기존 설정/비밀/DB/다른 플랫폼 실행 코드는 건드리지 않으며 이전 파일은 프로젝트 `.patch-backups`에 보관한다. `--apply`가 없으면 사전 검사만 한다.

```bash
(
set -e
cd ~/workspace
tar -xzf agent_platform_console_20260923.tar.gz
python3 agent_platform_console_20260923/apply_patch.py \
  --project-root ~/workspace/agent_project --apply
cd ~/workspace/agent_project/agent_platform
docker compose up -d --build --no-deps --wait agent-gateway
)
```

`http://<서버IP>:16100/console`에서 강력 새로고침(Ctrl+Shift+R) 후 연결한다. `도구 목록 / 도구 추가 / 실행 결과` 메뉴와 3단계 등록을 확인한다. 기존 초안/게시 도구가 열리는지, 시험용 API의 필수 입력·시험·사용 시작·결과가 표시되는지 확인한다. 이번 화면만 적용하기 위해 기존 A03 재기동/DB·GPU·OCR 전체 검사를 반복하지 않는다. 남아 있는 A04 인수는 [A04 검증 기록](testing-openapi-20260923.md)의 미확인 범위를 따른다.
