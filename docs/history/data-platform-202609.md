## 2026-09-16-06-unified-materials

**자료 수집·정리 목록 통합과 행별 실행/원본 다운로드**

목록의 원본 다운로드는 고정된 Streamlit 1.63의 deferred download를 사용한다. 렌더 시 원본 바이트를 읽지 않고 클릭 시에만 행별 원본 ID·Gateway·메타데이터로 GET한다. 크기/해시 검증 성공 후에만 저장된 파일명/확장자로 제공한다. 콜백은 세션 상태를 읽지 않으며 다른 행이나 페이지로 이동해도 원본 대상을 바꾸지 않는다. 오류를 원본 파일로 저장하거나 다른 결과로 대신하지 않는다. 정리 버튼은 기존 배포 확인과 멱등 요청/응답 유실 복구를 재사용한다.

콘솔 87개·요청 보관 8개·미리보기 11개·연결 검사 8개, 합계 114개 로컬 통과. 실제 Streamlit 다운로드 위젯의 지연 콜백 등록과 별도 스레드에서 PDF/HTML 바이트 보존·서로 다른 원본 식별·해시 오류 차단, 행별 정리/키 복구·미준비 PDF 차단·기존 URL·수집 완료 목록 갱신을 검증했다. 서버 Docker 빌드와 LAN 브라우저에서 실제 파일 저장은 별도 확인이다. 새 수집/OCR 작업이나 모델 재배포는 실행하지 않았다.

## 2026-09-16-08-data-inventory-ui

모델 플랫폼 화면을 기준으로 데이터 관리의 상단 브랜드/메뉴, 페이지 제목, 검색 도구줄, 목록 표, 상태 배지와 이전/다음 배치를 맞췄다. 자료 목록은 자료 이름·가져온 곳·파일 형식·상태·작업 열로 구성한다. 파일 이름을 눌러 원본 상세를 열고 오른쪽에는 내용 정리·원본 다운로드를 유지해 별도 내용 보기 버튼을 줄였다. 이름은 Markdown 이미지/링크로 해석되지 않게 표시한다.

OCR 조회·선택·접힌 연결 정보는 제목 아래 한 줄에 배치했다. 결과 목록과 웹 가져오기 내역에도 같은 표 스타일을 적용했다. 검색어를 입력하는 것만으로 조회 조건을 바꾸지 않고 조회 버튼을 눌러 적용하며, 페이지 이동은 적용한 조건을 유지한다. 현재 페이지 개수를 표시하고 이동 불가 버튼은 비활성화한다. 공개 UI의 메뉴는 자료 목록 / 결과 확인 두 개를 유지한다.

스타일은 데이터 콘솔의 data_style.py에 모아 독립 이미지 배포를 유지한다. 모델 플랫폼 파일을 런타임에 읽거나 가져오지 않는다. Dockerfile에 새 스타일 모듈 복사를 추가했다. 새 모델/정제 API, 표 비교 알고리즘, 저장 구조 변경은 없다. 원본 검증 다운로드·OCR 실행 직전 확인·멱등 요청·응답 유실 복구·기존 링크는 기존 구현을 사용한다.

로컬 콘솔 96개·요청 보관 8개·미리보기 11개·결과 연결 검사 8개, 합계 123개 통과. 검색 적용 시점과 파일 이름 클릭 대상, 파일명 Markdown 해석 차단을 추가로 확인했다. Python 3.10 문법도 검사했다. 이번 환경에서 실제 브라우저 렌더링은 검증하지 못했으며 서버 Docker 빌드·LAN 화면 배치/파일 저장은 적용 후 확인한다. GPU 추론은 실행하지 않았다. 검사 로그와 임시 설치 도구는 프로젝트 밖에 두고 서비스 데이터는 보존한다.


## 2026-09-16-09-catalog-deletion

자료 목록과 결과 확인에 행별 삭제 버튼과 확인창을 추가했다. 모델 관리와 같은 목록 삭제 의미로 단일 원본/정리 작업의 deleted_at을 저장하며 파일·메타데이터·출처·Operation은 보존한다. 본문/쿼리가 없는 UUID DELETE와 gRPC DeleteDocument/DeleteRun을 추가했다. 목록 검색/페이지 이동에서 제외하고 기존 ID의 조회·다운로드는 유지한다.

정리 결과는 연결된 Operation이 종료 상태인지 다시 확인해야 처음 삭제할 수 있다. 원본 목록 삭제는 새 정리 요청을 차단하며 이미 접수 중인 요청/실행은 취소하지 않는다. 같은 DELETE의 반복/동시 호출은 최초 시각을 유지하고 응답 유실 재확인은 원래 대상·서버를 사용한다. 이전 생성 요청의 멱등 재전송은 원래 결과 ID를 유지하며 삭제를 복원하지 않는다. 두 서비스 시작 시 nullable 컬럼만 추가한다.

UI는 삭제 범위와 파일 보존을 명시하고 취소·조회 시 DELETE를 보내지 않는다. 실패 시 확인창을 유지하며 성공 후 적용된 검색 조건으로 목록을 갱신한다. 삭제된 상세는 보관 안내와 원본 다운로드를 유지하고 새 정리를 막는다. 기존 요청 복구와 파일별 다운로드 검사를 유지했다.

Python 129개(콘솔 102·보관 8·미리보기 11·연결 8) 통과, Go 24개 통과·DB 연동 22개 skip. 관련 3개 서비스 실행 파일 컴파일 및 Python 3.10 문법 검사를 완료했다. 이번 로컬 환경에서는 PostgreSQL 기동이 불가해 DB 삭제/마이그레이션을 통과했다고 기록하지 않는다. 적용 절차는 기존 Data DB의 임시 테스트 스키마에서 4개 패키지의 모든 검사를 수행하며 실패/skip 시 서비스 갱신을 차단한다. 사용자 자료의 실제 DELETE, 새 수집/정리/GPU 추론은 실행하지 않았다.

## 2026-09-16 PDF 표 비교와 검토 화면

페이지 전체 OCR 교체 뒤 표별 비교·선택 단계를 추가했다. 물리적 셀 경계의 병합 범위를 복원하고 선 없는 표에는 원본 PDF 글자 위치를 활용한 추정 후보를 추가한다. 불일치·후보 누락은 검토 대상으로 남기며 양쪽 후보·본문 참조·선택 근거를 보존한다. 기본 화면에는 비교 개수만 표시하고 상세와 원본 영역은 요청 시 연다. 기존 결과 호환을 유지하며 새 정리부터 비교 기록을 만든다. 제공 샘플은 기존 OCR 응답 재생으로 검증했고 새 서버 GPU 추론은 수행하지 않았다. 현재 범위와 검사 수는 [표 비교](../data-platform/table-comparison.md)에 정리했다.

## 2026-09-16 OCR 우선과 파서 전용 선택
