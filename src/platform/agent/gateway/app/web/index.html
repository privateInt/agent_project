    n8n에서 여러 작업을 연결하고, 연결된 Agent의 실행 기록을 확인하세요.
    

    

    기존 n8n 업무흐름 연결
    n8n에 이미 있는 업무흐름의 편집 주소를 등록합니다. 새 워크플로 생성·게시·로그인은 n8n에서 진행합니다.
    사용 중인 Agent 버전만 선택할 수 있습니다. n8n에서도 이 버전을 사용하도록 설정하세요.
    

    선택한 업무흐름
    

    n8n에서 편집·실행
    Agent에 질문하면 Agent를 직접 실행합니다. n8n 전체 업무흐름은 n8n에서 실행하며, 별도 로그인이 필요합니다.
    

    n8n 접속 주소 확인
    서버 내부 주소가 등록돼 있으면 현재 PC에서 접속할 수 있는 n8n 주소를 입력하세요. 이 페이지에서 여는 주소만 바뀝니다.
    

    연결 이름·표시 관리
    연결을 숨겨도 n8n 게시 상태와 Agent는 바뀌지 않습니다. 실행 중지는 n8n에서 관리하세요.
    

    이 업무흐름에서 시작한 Agent 실행
    기록 조회를 누르면 저장된 Agent 실행을 확인합니다. n8n 전체 실행 상태와는 다릅니다.

    어떤 도구를 만들까요?
    

    

    사용할 지식을 선택하면 임베딩과 검색을 자동으로 연결합니다. 질문 벡터나 schema를 직접 입력하지 않아도 됩니다.
    

    서비스 연결 설정
    같은 서버의 기본 주소를 사용합니다. 별도 서버나 인증이 필요한 환경에서는 주소를 바꾸거나 저장된 연결을 선택하세요. 기본 연결은 처음 한 번 저장합니다.
    

    

    목록을 불러온 뒤 검색할 지식을 선택하세요.
    


    

    API 파일을 만들지 않고 요청 주소·방식·schema를 입력합니다. 다음 단계에서 인증을 설정하세요.
    전체 호출 주소를 넣으세요. 주소 변수는 /items/{item_id}처럼 표시합니다. ? 뒤의 값은 Query 입력으로 분리합니다.
    실행할 값이 아닌 값의 구조를 입력하세요. 예: {"query":"질문"}은 시험 단계에서 입력합니다.
    204는 응답 본문이 없는 성공입니다. 응답 schema를 보내지 않습니다.
    추가 입력 위치 · Path / Query / Header
    Path·Query·Header는 properties에 매개변수 이름을 둔 object schema를 사용합니다. 인증 키는 이곳에 넣지 말고 연결 설정에서 지정하세요. multipart·스트리밍·비동기 202 응답은 현재 지원하지 않습니다.
    고급: 벡터 검색 API를 직접 등록하기
    기존 검색 API는 질문 임베딩 벡터를 입력받습니다. 아래 버튼은 등록 양식만 채웁니다. 실제 시험값은 제공된 prepare_knowledge_tool_test.py로 준비합니다. 아직 API 호출은 하지 않습니다.
    같은 Docker 네트워크의 knowledge-gateway:8000을 기본 주소로 사용합니다. 환경이 다르면 요청 주소를 바꾸세요.
    

    어떤 기능을 연결할까요?
    서비스에서 제공하는 API 설명 파일(OpenAPI)을 올려 주세요. 파일을 분석한 후 사용할 기능 하나를 선택합니다.
    JSON·YAML · 최대 5 MiB
    이미 올린 파일 사용하기
    어떤 파일이 필요한가요?
    연결할 서비스의 관리자에게 OpenAPI JSON 또는 YAML 파일을 요청하세요. 예시 파일로 구조를 살펴볼 수 있습니다. 예시 주소는 실제로 호출할 수 없는 안내용 주소입니다.
    예시 파일 다운로드
    사용할 수 없는 기능
    파일을 분석하고 기능을 선택하세요.
